**EpoCanvas Docs** intègre en natif un multilinguisme complet au niveau du contenu : les textes d'interface (barre de navigation, barre latérale, aides à la recherche, etc.) ainsi que le corps du texte de chaque document existent en 10 versions linguistiques indépendantes. Lorsque le lecteur choisit une langue en haut à droite de la page, il est redirigé vers la version de l'article courant dans la langue cible, avec bascule simultanée du corps du texte et de l'interface.

---

## Liste des langues prises en charge

Le site propose actuellement 10 langues, dont le chinois simplifié est la langue par défaut :

| Langue | Nom de la langue | Préfixe URL | Abréviation dans l'interface |
| :--- | :--- | :--- | :--- |
| 简体中文 | **Chinois simplifié** (par défaut) | sans préfixe | ZH |
| 繁體中文 | Chinois traditionnel | `/zh-tw/` | TW |
| English | anglais | `/en/` | EN |
| 日本語 | japonais | `/ja/` | JA |
| 한국어 | coréen | `/ko/` | KO |
| Español | espagnol | `/es/` | ES |
| Français | français | `/fr/` | FR |
| Deutsch | allemand | `/de/` | DE |
| Русский | russe | `/ru/` | RU |
| Português | portugais | `/pt/` | PT |

La liste des langues se trouve dans `SUPPORTED_LANGUAGES` de `src/utils/i18n.ts`. Dans `astro.config.mjs`, `locales` enregistre les routes et `LOCALE_DIRS` reconnaît les répertoires des langues autres que celle par défaut. Ajouter une langue exige aussi de mettre à jour les dictionnaires et les scripts de contrôle.

## Comment changer de langue

1. Repérez le bouton de langue à droite de la barre de navigation en haut de la page (il affiche l'abréviation de la langue courante, par exemple `ZH`) ;
2. Cliquez sur le bouton : un menu déroulant liste les 10 langues disponibles ;
3. Cliquez sur la langue cible (par exemple `English` ou `日本語`) ;
4. Le navigateur charge la version de l'article courant dans la langue cible ; la navigation, la barre latérale, la table des matières et le corps du texte passent tous dans la langue cible.

## Règles d'URL

Les pages de chaque langue possèdent un préfixe d'URL qui leur est propre ; un même article ne diffère d'une langue à l'autre que par ce préfixe :

```text
/canvas/i18n/          → chinois simplifié (langue par défaut, sans préfixe)
/en/canvas/i18n/       → anglais
/ja/canvas/i18n/       → japonais
/zh-tw/canvas/i18n/    → chinois traditionnel
```

- L'information de langue est encodée directement dans l'URL ; une page obtenue après changement de langue peut être mise en favori et partagée telle quelle, et les moteurs de recherche peuvent indexer chaque langue séparément ;
- Les liens internes du site présents dans une page (navigation, barre latérale, liens recommandés dans le corps du texte) se voient ajouter automatiquement le préfixe de la langue courante : un lecteur qui enchaîne plusieurs articles dans une même langue ne retombe pas sur une page en chinois ;
- Chaque version linguistique est un jeu de pages statiques indépendantes généré au build ; l'attribut `<html lang>` de la page correspond à la langue, ce qui permet aux lecteurs d'écran et aux outils de traduction de l'identifier correctement.

## Que se passe-t-il en cas de traduction manquante ?

Lorsqu’une traduction manque, Starlight peut générer la route de la langue cible avec le corps en chinois simplifié. Il s’agit d’un repli technique, pas d’une politique de publication admise : la page peut déclarer la langue cible tout en affichant un texte chinois.

Ce projet impose de maintenir l’accueil et tous les articles dans les 10 langues. `node scripts/audit-i18n.mjs` contrôle les pages manquantes ou supplémentaires, le Frontmatter, les titres et la structure des blocs de code. Une traduction manquante entraîne un code de sortie non nul et bloque `pnpm run verify` ainsi que la CI. Traduisez tout ajout ou changement dans chaque langue avant de publier ; ne publiez pas d’abord le chinois pour traduire plus tard. La réussite de `pnpm run build` seule ne vaut pas validation avant publication.

## Principe de mise en œuvre

La capacité multilingue repose sur le mécanisme d'internationalisation d'Astro et de Starlight ; le processus de build est le suivant :

1. **Répertoires de contenu répartis par langue** : les documents de la langue par défaut sont placés dans `src/content/docs/` (chinois simplifié), ceux des autres langues dans `src/content/docs/<langue>/` ; l'arborescence correspond exactement à celle du chinois — par exemple, la version anglaise de « Prise en charge multilingue et changement de langue » se trouve dans `src/content/docs/en/canvas/i18n.md` ;
2. **Génération des pages de toutes les langues au build** : `astro build` lit la configuration `locales` de `astro.config.mjs` et génère un jeu complet de pages statiques pour chaque langue ;
3. **Rendu des libellés d'interface par langue** : les textes d'interface (navigation de la barre supérieure, aides à la recherche, titres de la table des matières, etc.) sont produits au build directement dans la langue correspondante par les composants via `getTranslation(key, lang)` ; la page ne contient aucun script de substitution à l'exécution ;
4. **Localisation automatique des liens internes du corps du texte** : le plugin `rehypeLocalizeInternalLinks` de la chaîne de build ajoute automatiquement le préfixe de la langue courante aux liens internes de type `/canvas/xxx` présents dans le corps du texte des traductions ;
5. **Recherche plein texte isolée par langue** : Pagefind construit un index indépendant pour chaque langue ; une recherche effectuée sur une page anglaise ne renvoie que des résultats en anglais.
6. **Images localisées et contrôles** : `rehypeLocalizeDiagramImages` remplace `/images/canvas/<fichier>` par `/images/canvas/<langue>/<fichier>` si une image traduite de même nom existe ; sinon, il conserve l’original. Mais `check-localized-images.mjs` exige les versions localisées, sauf pour les images réellement partagées, telles que les captures de services tiers inscrites dans `SHARED_ALLOWLIST`. Le repli ne dispense pas de traduire les images ;
7. **Encadrés et notes de bas de page suivent la langue de la page** : `rehypeLocalizeAsides` et `rehypeLocalizeFootnotes` réécrivent les titres des encadrés et les notes à partir du répertoire de langue du fichier source — Starlight déduit la langue via le chemin absolu à l'étape remark, alors que le build local lui transmet un chemin relatif, sans quoi tout retomberait en chinois ;
8. **hreflang et page 404** : à la fin du build, `hreflangXDefault()` ajoute à chaque page un `hreflang="x-default"` pointant vers la version en chinois simplifié, et `src/pages/404.astro` réutilise le même dictionnaire pour afficher son message dans la langue du navigateur, son menu de langues renvoyant à l'accueil de chaque langue.

## Développeurs : comment ajouter une langue ?

Exemple avec l'ajout de l'italien (Italiano, code `it`) :

1. **Enregistrer la route et le répertoire** : ajoutez `it: { label: 'Italiano', lang: 'it' }` à `locales` et `it` à `LOCALE_DIRS` dans `astro.config.mjs`, afin que liens, images, redirections et métadonnées de langue reconnaissent le nouveau répertoire.
2. **Traduire la barre latérale, les encadrés et les notes** : complétez `SIDEBAR_I18N` dans le même fichier ; ajoutez `it: 'it.json'` à `LOCALE_TRANSLATION_FILES` et les textes italiens à `FOOTNOTE_LABELS` et `FOOTNOTE_BACK_LABELS`.
3. **Traduire l’interface** : enregistrez code, nom, abréviation et répertoire dans `SUPPORTED_LANGUAGES` de `src/utils/i18n.ts`, puis complétez toutes les clés de `UI_TRANSLATIONS`, y compris la recherche, Pagefind et les messages 404.
4. **Traduire tout le contenu** : créez `src/content/docs/it/index.mdx` et les traductions complètes dans `src/content/docs/it/canvas/`, en correspondance exacte avec les fichiers de la langue par défaut. Conservez les clés du Frontmatter, les niveaux de titre et la structure des blocs de code. Copier le chinois comme texte provisoire ne constitue pas une traduction.
5. **Préparer les images localisées** : placez les fichiers de même nom dans `public/images/canvas/it/`. Seules les images réellement communes peuvent figurer dans `SHARED_ALLOWLIST` de `scripts/check-localized-images.mjs`. Avec le générateur de schémas, ajoutez `scripts/diagram-i18n/it.mjs` et son entrée dans `LOCALES` de `scripts/generate-diagram-locales.mjs` ; avec l’outil de captures, mettez à jour `LOCALES` et `SEARCH_WORDS` dans `scripts/capture-ui-shots.mjs`.
6. **Étendre les contrôles** : ajoutez `it` à `locales` et `LATIN` dans `scripts/audit-i18n.mjs`, à `LOCALES` dans `scripts/check-anchors.mjs` et à `LOCALE_DIRS` dans `scripts/check-localized-images.mjs`. Ajoutez `['it', 'it']` à la correspondance langue/répertoire `LANG_DIRS` dans `scripts/check-links.mjs`. `scripts/check-images.mjs` parcourt récursivement tous les répertoires d’images, sans liste de langues à modifier.
7. **Contrôler les sources et les images** : lancez `node scripts/audit-i18n.mjs` et `node scripts/check-images.mjs` à la racine du dépôt. Le second ne vérifie que l’en-tête PNG et la taille minimale, pas les traductions ni la mise en page.
8. **Vérifier avant publication** : lancez `pnpm run verify`, qui construit le site puis contrôle les références aux images localisées, les liens, les ancres et les métadonnées de langue. Avec `pnpm run preview`, examinez l’accueil, les articles, le changement de langue et la recherche globale dans la nouvelle langue. Corrigez tous les échecs au lieu de supprimer des contrôles pour publier.

## Développeurs : comment ajouter ou modifier un libellé d'interface ?

Lors de l'ajout d'un élément d'interface, complétez les libellés dans `UI_TRANSLATIONS` de `src/utils/i18n.ts` :

```typescript
// Chemin du fichier : src/utils/i18n.ts
// Le dictionnaire est organisé en deux niveaux « langue → clé d'entrée », dans l'ordre de lecture de getTranslation
export const UI_TRANSLATIONS: Record<string, Record<string, string>> = {
  // Étape 1 : ajouter les textes dans la langue par défaut zh-CN (à défaut, l'interface affiche le nom de la clé)
  'zh-CN': {
    'nav.plugins': '插件生态',
    // ...autres textes déjà présents
  },
  // Étape 2 : compléter la traduction des mêmes clés pour les autres langues ; sans traduction, retour au chinois
  en: {
    'nav.plugins': 'Plugins',
  },
  ja: {
    'nav.plugins': 'プラグイン',
  },
};
```

Appelez ensuite `getTranslation` dans le composant en lui passant la langue courante :

```astro
---
import { getLangFromLocale, getTranslation, localizedHref } from '../../utils/i18n';
const lang = getLangFromLocale(Astro.currentLocale);
---

<a href={localizedHref('/plugins/', lang)}>{getTranslation('nav.plugins', lang)}</a>
```

Les libellés sont rendus au build sous forme de texte statique dans la langue correspondante, sans surcoût à l'exécution.

Cet exemple ne montre que trois langues. Toute nouvelle clé doit être traduite dans chaque langue enregistrée ; le repli sur le chinois est une protection, pas une traduction achevée.
