**EpoCanvas Docs** intègre en natif un multilinguisme complet au niveau du contenu : les textes d'interface (barre de navigation, barre latérale, aides à la recherche, etc.) ainsi que le corps du texte de chaque document existent en 10 versions linguistiques indépendantes. Lorsque le lecteur choisit une langue en haut à droite de la page, il est redirigé vers la version de l'article courant dans la langue cible, avec bascule simultanée du corps du texte et de l'interface.

---

## Liste des langues prises en charge

Le site propose actuellement 10 langues, dont le chinois simplifié est la langue par défaut :

| Langue | Nom de la langue | Préfixe URL | Abréviation dans l'interface |
| :--- | :--- | :--- | :--- |
| 简体中文 | **简体中文** (par défaut) | sans préfixe | ZH |
| 繁體中文 | 繁體中文 | `/zh-tw/` | TW |
| English | anglais | `/en/` | EN |
| 日本語 | japonais | `/ja/` | JA |
| 한국어 | coréen | `/ko/` | KO |
| Español | espagnol | `/es/` | ES |
| Français | français | `/fr/` | FR |
| Deutsch | allemand | `/de/` | DE |
| Русский | russe | `/ru/` | RU |
| Português | portugais | `/pt/` | PT |

La liste des langues est définie dans `SUPPORTED_LANGUAGES` du fichier `src/utils/i18n.ts`, et le routage des langues est enregistré dans la configuration `locales` de `astro.config.mjs` ; les deux doivent rester cohérents.

## Comment changer de langue

1. Repérez le bouton de langue à droite de la barre de navigation en haut de la page (il affiche l'abréviation de la langue courante, par exemple `ZH`) ;
2. Cliquez sur le bouton : un menu déroulant liste les 10 langues disponibles ;
3. Cliquez sur la langue cible (par exemple `English` ou `日本語`) ;
4. Le navigateur charge la version de l'article courant dans la langue cible ; la navigation, la barre latérale, la table des matières et le corps du texte passent tous dans la langue cible.

## Règles d'URL

Les pages de chaque langue possèdent un préfixe d'URL qui leur est propre ; un même article ne diffère d'une langue à l'autre que par ce préfixe :

```text
/canvas/i18n/          → chinois simplifié (langue par défaut, sans préfixe)
/en/canvas/i18n/       → anglais
/ja/canvas/i18n/       → japonais
/zh-tw/canvas/i18n/    → chinois traditionnel
```

- L'information de langue est encodée directement dans l'URL ; une page obtenue après changement de langue peut être mise en favori et partagée telle quelle, et les moteurs de recherche peuvent indexer chaque langue séparément ;
- Les liens internes du site présents dans une page (navigation, barre latérale, liens recommandés dans le corps du texte) se voient ajouter automatiquement le préfixe de la langue courante : un lecteur qui enchaîne plusieurs articles dans une même langue ne retombe pas sur une page en chinois ;
- Chaque version linguistique est un jeu de pages statiques indépendantes généré au build ; l'attribut `<html lang>` de la page correspond à la langue, ce qui permet aux lecteurs d'écran et aux outils de traduction de l'identifier correctement.

## Que se passe-t-il en cas de traduction manquante ?

Le système applique une stratégie de repli sur la langue par défaut pour les traductions manquantes : lorsqu'un document n'a pas encore de traduction dans une langue donnée, la page de cette langue affiche le contenu par défaut en chinois simplifié, tandis que le reste de la page (navigation, barre latérale, textes d'interface) reste dans la langue cible ; aucune erreur 404 ni page blanche n'apparaît.

L'avantage de cette stratégie : lors de l'ajout d'un document, il n'est pas nécessaire d'attendre que les traductions dans toutes les langues soient prêtes ; on publie d'abord la version chinoise, puis il suffit de relancer le build une fois les traductions complétées.

## Principe de mise en œuvre

La capacité multilingue repose sur le mécanisme d'internationalisation d'Astro et de Starlight ; le processus de build est le suivant :

1. **Répertoires de contenu répartis par langue** : les documents de la langue par défaut sont placés dans `src/content/docs/` (chinois simplifié), ceux des autres langues dans `src/content/docs/<langue>/` ; l'arborescence correspond exactement à celle du chinois — par exemple, la version anglaise de « Prise en charge multilingue et changement de langue » se trouve dans `src/content/docs/en/canvas/i18n.md` ;
2. **Génération des pages de toutes les langues au build** : `astro build` lit la configuration `locales` de `astro.config.mjs` et génère un jeu complet de pages statiques pour chaque langue ;
3. **Rendu des libellés d'interface par langue** : les textes d'interface (navigation de la barre supérieure, aides à la recherche, titres de la table des matières, etc.) sont produits au build directement dans la langue correspondante par les composants via `getTranslation(key, lang)` ; la page ne contient aucun script de substitution à l'exécution ;
4. **Localisation automatique des liens internes du corps du texte** : le plugin `rehypeLocalizeInternalLinks` de la chaîne de build ajoute automatiquement le préfixe de la langue courante aux liens internes de type `/canvas/xxx` présents dans le corps du texte des traductions ;
5. **Recherche plein texte isolée par langue** : Pagefind construit un index indépendant pour chaque langue ; une recherche effectuée sur une page anglaise ne renvoie que des résultats en anglais.

## Développeurs : comment ajouter une langue ?

Exemple avec l'ajout de l'italien (Italiano, code `it`) :

1. **Enregistrer la route de la langue** : ajouter `it: { label: 'Italiano', lang: 'it' }` dans `locales` de `astro.config.mjs` ;
2. **Compléter les textes de la barre latérale** : dans `SIDEBAR_I18N` du même fichier, ajouter les traductions `it` pour tous les groupes et entrées ;
3. **Compléter les libellés d'interface** : enregistrer la langue (code, nom, abréviation, préfixe URL) dans `SUPPORTED_LANGUAGES` de `src/utils/i18n.ts`, et compléter les libellés d'interface de cette langue dans `UI_TRANSLATIONS` ;
4. **Traduire le contenu des documents** : créer le répertoire `src/content/docs/it/` et y placer les traductions en respectant l'arborescence de la version chinoise. Les pages non traduites affichent d'abord le contenu chinois par repli ; elles peuvent être complétées progressivement ;
5. **Relancer le build** : exécuter `pnpm run build` ; les pages de la nouvelle langue et les index de recherche sont alors générés.

## Développeurs : comment ajouter ou modifier un libellé d'interface ?

Lors de l'ajout d'un élément d'interface, complétez les libellés dans `UI_TRANSLATIONS` de `src/utils/i18n.ts` :

```typescript
// 文件路径: src/utils/i18n.ts
// 字典按「语言 → 词条键」两级组织，与 getTranslation 的读取顺序一致
export const UI_TRANSLATIONS: Record<string, Record<string, string>> = {
  // 第一步：在默认语言 zh-CN 里加词条（缺失时界面回退显示键名）
  'zh-CN': {
    'nav.plugins': '插件生态',
    // ...其余已有词条
  },
  // 第二步：给其它语言补同一键名的翻译，没补的语言自动回退中文
  en: {
    'nav.plugins': 'Plugins',
  },
  ja: {
    'nav.plugins': 'プラグイン',
  },
};
```

Appelez ensuite `getTranslation` dans le composant en lui passant la langue courante :

```astro
---
import { getLangFromLocale, getTranslation } from '../../utils/i18n';
const lang = getLangFromLocale(Astro.currentLocale);
---

<a href={localizedHref('/plugins/', lang)}>{getTranslation('nav.plugins', lang)}</a>
```

Les libellés sont rendus au build sous forme de texte statique dans la langue correspondante, sans surcoût à l'exécution.
