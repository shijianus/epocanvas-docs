**EpoCanvas Docs** 內建了完整的內容級多語系：導覽列、側邊欄、搜尋提示等介面文字，以及每一篇文件的內文，都提供 10 種語言的獨立版本。讀者在頁面右上角選擇語言後，會跳轉到同一篇文章的目標語言版本，內文與介面一起切換。

---

## 支援的語言清單

網站目前提供 10 種語言，其中簡體中文是預設語言：

| 語言 | 語言名稱 | URL 前綴 | 介面縮寫 |
| :--- | :--- | :--- | :--- |
| 简体中文 | **簡體中文**（預設） | 無前綴 | ZH |
| 繁體中文 | 繁體中文 | `/zh-tw/` | TW |
| English | 英文 | `/en/` | EN |
| 日本語 | 日文 | `/ja/` | JA |
| 한국어 | 韓文 | `/ko/` | KO |
| Español | 西班牙文 | `/es/` | ES |
| Français | 法文 | `/fr/` | FR |
| Deutsch | 德文 | `/de/` | DE |
| Русский | 俄文 | `/ru/` | RU |
| Português | 葡萄牙文 | `/pt/` | PT |

語言清單定義在 `src/utils/i18n.ts` 的 `SUPPORTED_LANGUAGES`；`astro.config.mjs` 的 `locales` 註冊路由，`LOCALE_DIRS` 識別非預設語言目錄。新增語言還須同步翻譯字典與檢查腳本，不能只改 `locales`。

## 如何切換語言

1. 在頁面頂部導覽列右側找到語言按鈕（顯示目前語言的縮寫，如 `ZH`）；
2. 點擊按鈕，下拉選單列出全部 10 種語言；
3. 點擊目標語言（例如 `English` 或 `日本語`）；
4. 瀏覽器跳轉到目前這篇文章的目標語言版本，導覽、側邊欄、目錄與內文一起變成目標語言。

## URL 規則

每種語言的頁面有獨立的 URL 前綴，同一篇文章在不同語言下只有前綴不同：

```text
/canvas/i18n/          → 簡體中文（預設語言，無前綴）
/en/canvas/i18n/       → 英文
/ja/canvas/i18n/       → 日文
/zh-tw/canvas/i18n/    → 繁體中文
```

- 語言資訊直接編碼在 URL 裡，切換後的頁面可以直接加入書籤、分享，搜尋引擎也能按語言分別收錄；
- 頁面內出現的站內連結（導覽、側邊欄、內文中的推薦連結）都會自動帶上目前語言的前綴，讀者在某一語言內連續閱讀時不會跳回中文頁；
- 每個語言版本都是建置期產生的獨立靜態頁面，頁面的 `<html lang>` 屬性與語言一致，螢幕閱讀器和翻譯工具可以正確識別。

## 譯文缺失怎麼辦

Starlight 在文件缺少譯文時，可以用預設的簡體中文內文產生目標語言路由。這是框架的技術備援，不是本專案允許的發布方式：頁面的語言宣告可能仍是目標語言，內文卻是中文。

本專案要求首頁與全部內文在 10 種語言中成套維護。`node scripts/audit-i18n.mjs` 會檢查缺頁、多餘頁、Frontmatter、標題與程式碼圍欄結構；缺譯會回傳非零結束碼，阻擋 `pnpm run verify` 與 CI。新增或修改文件時，須同步完成全部語言的對應內容再發布，不能先發中文版、之後補譯。僅 `pnpm run build` 成功不代表通過發布檢查。

## 實作原理

多語系能力由 Astro 與 Starlight 的國際化機制承載，建置流程如下：

1. **內容目錄按語言劃分**：預設語言的文件放在 `src/content/docs/`（簡體中文），其他語言放在 `src/content/docs/<語言>/` 下，目錄結構與中文完全對應，例如英文版《多語系支援與閱讀切換》是 `src/content/docs/en/canvas/i18n.md`；
2. **建置期產生全部語言頁面**：`astro build` 讀取 `astro.config.mjs` 中的 `locales` 設定，為每種語言產生一套完整靜態頁面；
3. **介面字串按語言渲染**：頂欄導覽、搜尋提示、目錄標題等介面文字由各元件呼叫 `getTranslation(key, lang)` 在建置期直接輸出對應語言，頁面裡沒有執行時替換腳本；
4. **內文內部連結自動在地化**：建置管線中的 `rehypeLocalizeInternalLinks` 外掛會把譯文內文裡的 `/canvas/xxx` 內部連結自動加上目前語言前綴；
5. **全文搜尋按語言隔離**：Pagefind 為每種語言建立獨立索引，在英文頁面搜尋只會回傳英文結果。
6. **內文圖片在地化與檢查**：`rehypeLocalizeDiagramImages` 在有同名譯圖時，將 `/images/canvas/<檔名>` 改為 `/images/canvas/<語言>/<檔名>`；否則技術上保留原圖。但發布檢查 `check-localized-images.mjs` 要求對應語言圖片齊全，僅 `SHARED_ALLOWLIST` 登記的第三方介面截圖等真正共用圖片可例外，不能靠原圖回退略過翻譯；
7. **提示框與註腳依語言輸出**：`rehypeLocalizeAsides` 與 `rehypeLocalizeFootnotes` 依原始檔所在語言目錄改寫提示框標題與註腳文字——Starlight 在 remark 階段以檔案絕對路徑推斷語言，而本機建置傳給它的是相對路徑，不處理就會全部回退成中文；
8. **hreflang 與 404 頁**：`hreflangXDefault()` 於建置完成後為每個頁面補一條 `hreflang="x-default"`，指向簡體中文版本；`src/pages/404.astro` 沿用同一份詞條字典，依瀏覽器語言輸出提示文字，頁面上的語言選單指向各語言首頁。

## 開發者：如何新增一種語言？

以新增義大利文（Italiano，代碼 `it`）為例：

1. **註冊路由與目錄**：在 `astro.config.mjs` 的 `locales` 加入 `it: { label: 'Italiano', lang: 'it' }`，同時在 `LOCALE_DIRS` 加入 `it`，讓內部連結、圖片、重新導向與語言宣告處理識別新目錄。
2. **翻譯側邊欄、提示框與註腳**：補齊同一檔案的 `SIDEBAR_I18N`；在 `LOCALE_TRANSLATION_FILES` 登記 `it: 'it.json'`，並補充 `FOOTNOTE_LABELS` 與 `FOOTNOTE_BACK_LABELS` 的義大利文文案。
3. **翻譯介面字串**：在 `src/utils/i18n.ts` 的 `SUPPORTED_LANGUAGES` 登記代碼、名稱、縮寫與目錄，在 `UI_TRANSLATIONS` 補齊全部鍵，包括搜尋、Pagefind 與 404 提示。
4. **翻譯全部內容**：建立 `src/content/docs/it/index.mdx`，並在 `src/content/docs/it/canvas/` 放入與預設語言一一對應的完整譯文。維持 Frontmatter 欄位、標題層級與程式碼圍欄結構一致；複製中文占位不算完成翻譯。
5. **準備在地化圖片**：將同名譯圖放入 `public/images/canvas/it/`，僅真正共用圖片可登記到 `scripts/check-localized-images.mjs` 的 `SHARED_ALLOWLIST`。使用現有圖表產生工具時，補充 `scripts/diagram-i18n/it.mjs` 並在 `scripts/generate-diagram-locales.mjs` 的 `LOCALES` 登記；使用截圖工具時，同步 `scripts/capture-ui-shots.mjs` 的 `LOCALES` 與 `SEARCH_WORDS`。
6. **同步檢查範圍**：在 `scripts/audit-i18n.mjs` 的 `locales` 與 `LATIN` 加入 `it`；在 `scripts/check-anchors.mjs` 的 `LOCALES`、`scripts/check-localized-images.mjs` 的 `LOCALE_DIRS` 加入 `it`；在 `scripts/check-links.mjs` 的語言代碼與目錄對照 `LANG_DIRS` 加入 `['it', 'it']`。`scripts/check-images.mjs` 自動遞迴掃描全部圖片目錄，不須另加語言清單。
7. **先檢查原始檔與圖片**：在儲存庫根目錄執行 `node scripts/audit-i18n.mjs` 與 `node scripts/check-images.mjs`。後者只檢查 PNG 檔頭與最小體積，不能取代人工核對圖中文字和版面。
8. **完整驗證後發布**：執行 `pnpm run verify`，建置後會檢查在地化圖片引用、連結、錨點與語言宣告；再用 `pnpm run preview` 檢查新語言首頁、內文、語言切換與全站搜尋。修復全部失敗項目，不要藉由刪除檢查來發布。

## 開發者：如何新增或修改介面字串？

新增介面元素時，在 `src/utils/i18n.ts` 的 `UI_TRANSLATIONS` 中補充字串：

```typescript
// 檔案路徑: src/utils/i18n.ts
// 字典按「語言 → 字串鍵」兩層組織，與 getTranslation 的讀取順序一致
export const UI_TRANSLATIONS: Record<string, Record<string, string>> = {
  // 第一步：在預設語言 zh-CN 裡加字串（缺失時介面回退顯示鍵名）
  'zh-CN': {
    'nav.plugins': '插件生态',
    // ...其餘已有字串
  },
  // 第二步：給其它語言補同一鍵名的翻譯，沒補的語言自動回退中文
  en: {
    'nav.plugins': 'Plugins',
  },
  ja: {
    'nav.plugins': 'プラグイン',
  },
};
```

然後在元件中呼叫 `getTranslation` 並傳入目前語言：

```astro
---
import { getLangFromLocale, getTranslation, localizedHref } from '../../utils/i18n';
const lang = getLangFromLocale(Astro.currentLocale);
---

<a href={localizedHref('/plugins/', lang)}>{getTranslation('nav.plugins', lang)}</a>
```

字串在建置期渲染為對應語言的靜態文字，沒有執行時開銷。

上例只節選三個語言分支；新增字串仍須在全部已註冊語言中補齊。中文回退僅用於容錯，不代表翻譯完成。
