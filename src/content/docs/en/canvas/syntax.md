Every example on this page is live syntax — what you see is the rendered result. This page is itself a working example.

## 1. The Four Colored Aside Types

Asides use the triple-colon syntax: start with `:::type`, end with `:::`, and put the content in between. The site is built on Starlight and supports the four types **note, tip, caution, and danger**.

### Syntax vs. Rendered Result

:::note
**note (supplementary information)**: for background knowledge, extra design details, or prerequisites.
:::

:::tip
**tip (practical technique)**: for sharing small tricks or best practices that improve efficiency.
:::

:::caution
**caution (warning)**: flags possible compatibility conflicts, potential errors, or operations that need special care.
:::

:::danger
**danger (high-severity warning)**: the highest level of warning, for data loss, overwriting production environments, or irreversible operations.
:::

### Asides Can Contain Any Content

Inside an aside you can keep using lists, code blocks, tables, and other syntax:

:::tip[Speed Up Installation]
Installing dependencies with pnpm is much faster than with npm:

```bash
npm install -g pnpm
```
:::

:::caution
Two common invalid forms to avoid:

- GitHub-style `> [!NOTE]` blockquote syntax is not supported and is displayed as-is, like an ordinary blockquote;
- `:::important` and `:::warning` are **not supported types on this site**: they do not raise an error but are silently rendered as ordinary paragraphs with no aside styling.

When migrating from GitHub docs, rewrite `> [!NOTE]` as `:::note`, `> [!WARNING]` as `:::caution`, and `> [!CAUTION]` as `:::danger`.
:::

## 2. Advanced Code Block Formatting

### 2.1 Filename Titles and Line Highlighting

Annotate the first line of the code fence with `title="file path"` and use `{line number}` to highlight key lines:

````markdown
```typescript title="src/config/site.ts" {2}
export const siteConfig = {
  name: 'EpoCanvas Docs', // this line gets a highlighted background
  version: '1.2.0',
};
```
````

**Rendered result:**

```typescript title="src/config/site.ts" {2}
export const siteConfig = {
  name: 'EpoCanvas Docs',
  version: '1.2.0',
};
```

### 2.2 Code Diffs (diff)

When showing a configuration upgrade or a refactoring, the `diff` language makes changes obvious: lines starting with `-` render as removed and lines starting with `+` as added:

````markdown
```diff
  export default defineConfig({
-   site: 'http://localhost:3000',
+   site: 'https://docs.epocanvas.com',
  });
```
````

**Rendered result:**

```diff
  export default defineConfig({
-   site: 'http://localhost:3000',
+   site: 'https://docs.epocanvas.com',
  });
```

### 2.3 Terminal Commands

Terminal languages such as `bash`, `sh`, and `powershell` render with a dark, terminal-style frame:

```bash
pnpm run build
```

## 3. How to Insert Diagrams?

The current version has **no built-in rendering for text-based diagram languages such as Mermaid**. Writing a ` ```mermaid ` fence only displays the source as an ordinary code block; no diagram is generated.

The recommended approach: write the diagram in a tool such as [mermaid.live](https://mermaid.live) and export it as an **SVG vector image**, save it to `public/images/canvas/`, and insert it with image syntax. The architecture diagrams and language-switching flow diagrams on this site were produced this way:

![System architecture diagram](/images/canvas/docs-architecture.svg)

*Figure: an architecture diagram inserted as an SVG image; it stays sharp at any zoom level.*

If you truly need Mermaid source to render directly into a diagram, you must add an extra rendering plugin (such as `rehype-mermaid`) to the project. That falls under customization, so weigh the maintenance cost before adding it.

## 4. Other Useful Formatting

- Inline code: `pnpm run dev`, rendered as monospace text in the theme color;
- Keyboard keys: <kbd>Ctrl</kbd> + <kbd>K</kbd>, rendered in a keycap style;
- Task lists:

```markdown
- [x] Syntax highlighting supported
- [x] One-click copy supported
- [ ] Built-in Mermaid rendering (planned)
```

This renders as list items with check states.

### 4.1 Footnotes

To cite sources or add supplementary notes, use the GFM footnote syntax:

````markdown
The static index is generated by Pagefind at build time[^pagefind].

[^pagefind]: [Pagefind documentation](https://pagefind.app/) — a local search library for static sites.
````

**Rendered result:** a numbered superscript jump marker[^pagefind-demo] appears at the end of the sentence; clicking it smooth-scrolls to the footnote list at the bottom of the page.

[^pagefind-demo]: This is the actual footnote rendered at the bottom of this page.
