## 1. Четыре цветные выноски

Выноски используют синтаксис тройного двоеточия: открываются `:::type`, закрываются `:::`, между ними пишется содержимое. Сайт основан на Starlight и поддерживает четыре типа: **note, tip, caution, danger**.

### Синтаксис и реальный эффект: сравнение

:::note
**note (дополнительное пояснение)**: для знакомства с контекстом, дополнения деталей замысла или указания предварительных зависимостей.
:::

:::tip
**tip (полезный приём)**: для обмена небольшими приёмами, повышающими эффективность работы, или лучшими практиками.
:::

:::caution
**caution (предупреждение)**: о возможных конфликтах совместимости, потенциальных ошибках или операциях, требующих особого внимания.
:::

:::danger
**danger (предупреждение о высокой опасности)**: предупреждение высшего уровня о потере данных, перезаписи в production-окружении или необратимых операциях.
:::

### Внутри выноски может быть любое содержимое

Внутри выноски можно продолжать использовать списки, блоки кода, таблицы и другой синтаксис:

:::tip[Ускорение установки]
Установка зависимостей через pnpm заметно быстрее, чем через npm:

```bash
npm install -g pnpm
```
:::

:::caution
Два распространённых нерабочих варианта, которых стоит избегать:

- синтаксис цитаты в стиле GitHub `> [!NOTE]` не поддерживается и отобразится как есть, обычной цитатой;
- `:::important` и `:::warning` **не относятся к поддерживаемым на этом сайте типам**: ошибки не будет, но они молча отрендерятся как обычные абзацы, без какого-либо оформления выноски.

Перенося документацию с GitHub, перепишите `> [!NOTE]` в `:::note`, `> [!WARNING]` в `:::caution`, `> [!CAUTION]` в `:::danger`.
:::

## 2. Расширенное оформление блоков кода

### 2.1 Заголовок с именем файла и подсветка заданных строк

В первой строке кодового ограждения укажите `title="путь к файлу"` и подсветите важные строки через `{номера строк}`:

````markdown
```typescript title="src/config/site.ts" {2}
export const siteConfig = {
  name: 'EpoCanvas Docs', // эта строка будет выделена подсветкой фона
  version: '1.2.0',
};
```
````

**Результат рендеринга:**

```typescript title="src/config/site.ts" {2}
export const siteConfig = {
  name: 'EpoCanvas Docs',
  version: '1.2.0',
};
```

### 2.2 Сравнение изменений кода (diff)

Показывая обновление конфигурации или рефакторинг кода, используйте язык `diff`, чтобы изменения были видны с первого взгляда: строки, начинающиеся с `-`, отображаются как удалённые, начинающиеся с `+` — как добавленные:

````markdown
```diff
  export default defineConfig({
-   site: 'http://localhost:3000',
+   site: 'https://docs.epocanvas.com',
  });
```
````

**Результат рендеринга:**

```diff
  export default defineConfig({
-   site: 'http://localhost:3000',
+   site: 'https://docs.epocanvas.com',
  });
```

### 2.3 Терминальные команды

Терминальные языки `bash`, `sh`, `powershell` и другие рендерятся с тёмной рамкой в стиле терминала:

```bash
pnpm run build
```

## 3. Как вставить диаграмму

В текущей версии **рендеринг текстовых диаграмм вроде Mermaid не встроен**. Написанное напрямую ограждение ` ```mermaid ` отобразится как обычный блок кода с исходным кодом, без построения графики.

Рекомендуемый подход: написать диаграмму и экспортировать **векторный SVG** в инструменте вроде [mermaid.live](https://mermaid.live), сохранить его в `public/images/canvas/` и вставить синтаксисом изображений. Именно так сделаны архитектурная схема и схема процесса переключения языка на этом сайте:

![Схема архитектуры системы](/images/canvas/docs-architecture.svg)

*Рисунок: архитектурная схема, вставленная как SVG-изображение, — масштабируется без потери чёткости.*

Если всё же нужно, чтобы исходник Mermaid рендерился в график напрямую, в проект придётся добавить дополнительный плагин рендеринга (например, `rehype-mermaid`); это уже доработка проекта — вводите её после оценки затрат на сопровождение.

## 4. Другая полезная вёрстка

- встроенный код: `pnpm run dev` — рендерится моноширинным шрифтом цвета темы;
- клавиши: <kbd>Ctrl</kbd> + <kbd>K</kbd> — рендерятся в стиле клавиатурных клавиш;
- список задач:

```markdown
- [x] Поддержка подсветки синтаксиса
- [x] Поддержка копирования одним нажатием
- [ ] Встроенный рендеринг Mermaid (в планах)
```

Рендерится в виде пунктов списка с состоянием отметки.

Когда нужно указать источник материала или добавить пояснение, используйте синтаксис сносок GFM:

````markdown
Статический индекс генерируется Pagefind при сборке[^pagefind].

[^pagefind]: [Официальная документация Pagefind](https://pagefind.app/) — библиотека локального поиска для статических сайтов.
````

**Результат рендеринга:** в конце фразы в основном тексте появится надстрочный маркер перехода с номером[^pagefind-demo], по клику происходит плавный переход к списку сносок внизу страницы.
