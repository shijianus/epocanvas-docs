В **EpoCanvas Docs** встроена полноценная многоязычность на уровне контента: тексты интерфейса — панель навигации, боковая панель, подсказки поиска и другие — и основной текст каждого документа доступны в 10 отдельных языковых версиях. Выбрав язык в правом верхнем углу страницы, читатель переходит к той же статье на выбранном языке: переключаются и основной текст, и интерфейс.

---

## Как переключить язык

1. Найдите справа в верхней панели навигации кнопку языка (на ней показана аббревиатура текущего языка, например `ZH`);
2. Кликните кнопку — в выпадающем меню перечислены все 10 языков;
3. Кликните нужный язык (например, `English` или `日本語`);
4. Браузер перейдёт к версии текущей статьи на выбранном языке: навигация, боковая панель, оглавление и основной текст одновременно переключатся на этот язык.

## Правила URL

У каждого языка свой префикс URL; у одной и той же статьи на разных языках различается только префикс:

```text
/canvas/i18n/          → упрощённый китайский (язык по умолчанию, без префикса)
/en/canvas/i18n/       → английский
/ja/canvas/i18n/       → японский
/zh-tw/canvas/i18n/    → традиционный китайский
```

- Информация о языке закодирована прямо в URL: страницу после переключения можно сразу добавлять в закладки и делиться ею, а поисковые системы индексируют языки по отдельности;
- Внутренние ссылки на странице (навигация, боковая панель, рекомендательные ссылки в основном тексте) автоматически получают префикс текущего языка, поэтому при непрерывном чтении в рамках одного языка читатель не возвращается на китайские страницы;
- Каждая языковая версия — отдельная статическая страница, сгенерированная на этапе сборки; атрибут `<html lang>` страницы соответствует языку, поэтому скринридеры и средства перевода распознают его корректно.

## Что происходит при отсутствии перевода

Если перевод отсутствует, Starlight может создать маршрут целевого языка с основным текстом на упрощённом китайском. Это технический резервный механизм, а не допустимый порядок публикации: язык страницы может быть объявлен целевым, хотя текст остаётся китайским.

Проект требует поддерживать главную страницу и все статьи на всех 10 языках. `node scripts/audit-i18n.mjs` проверяет отсутствующие и лишние страницы, Frontmatter, заголовки и структуру блоков кода. Отсутствие перевода приводит к ненулевому коду выхода и блокирует `pnpm run verify` и CI. Перед публикацией добавьте или обновите материал на каждом языке; нельзя сначала публиковать китайскую версию, а затем дополнять переводы. Успех `pnpm run build` сам по себе не означает прохождения проверок публикации.

## Как это реализовано

Многоязычность обеспечивается механизмами интернационализации Astro и Starlight. Процесс сборки выглядит так:

1. **Каталоги контента разделены по языкам**: документы языка по умолчанию лежат в `src/content/docs/` (упрощённый китайский), остальные языки — в `src/content/docs/<язык>/`; структура каталогов полностью соответствует китайской, например английская версия «Многоязычность и переключение языков» — это `src/content/docs/en/canvas/i18n.md`;
2. **При сборке генерируются страницы всех языков**: `astro build` читает конфигурацию `locales` из `astro.config.mjs` и создаёт полный набор статических страниц для каждого языка;
3. **Интерфейсные строки рендерятся по языкам**: тексты интерфейса — навигация в верхней панели, подсказки поиска, заголовки оглавления и т.д. — компоненты выводят на этапе сборки через `getTranslation(key, lang)` сразу на нужном языке; скриптов подмены во время выполнения на странице нет;
4. **Внутренние ссылки в тексте локализуются автоматически**: плагин `rehypeLocalizeInternalLinks` в конвейере сборки автоматически добавляет префикс текущего языка к внутренним ссылкам `/canvas/xxx` в переведённом тексте;
5. **Полнотекстовый поиск изолирован по языкам**: Pagefind строит отдельный индекс для каждого языка, поэтому поиск на английской странице возвращает только английские результаты.
6. **Локализованные изображения и проверки**: `rehypeLocalizeDiagramImages` меняет `/images/canvas/<файл>` на `/images/canvas/<язык>/<файл>`, если перевод изображения с таким именем существует; иначе сохраняет оригинал. Но `check-localized-images.mjs` требует локализованные изображения, кроме действительно общих ресурсов, например снимков сторонних интерфейсов из `SHARED_ALLOWLIST`. Резервный оригинал не заменяет перевод;
7. **Выноски и сноски следуют языку страницы**: `rehypeLocalizeAsides` и `rehypeLocalizeFootnotes` подменяют заголовки выносок и текст сносок по каталогу языка исходника — Starlight определяет язык на этапе remark по абсолютному пути, а локальная сборка передаёт относительный, без этого всё откатывалось бы к китайскому;
8. **hreflang и страница 404**: после сборки `hreflangXDefault()` добавляет на каждую страницу ссылку `hreflang="x-default"` на упрощённую китайскую версию, а `src/pages/404.astro` использует тот же словарь, чтобы вывести текст по языку браузера; меню языков на ней ведёт на главную каждого языка.

## Для разработчиков: как добавить новый язык

Пример: добавление итальянского языка (Italiano, код `it`):

1. **Зарегистрируйте маршрут и каталог**: добавьте `it: { label: 'Italiano', lang: 'it' }` в `locales` и `it` в `LOCALE_DIRS` в `astro.config.mjs`, чтобы обработка ссылок, изображений, перенаправлений и языковых метаданных распознавала новый каталог.
2. **Переведите боковую панель, выноски и сноски**: заполните `SIDEBAR_I18N` в том же файле; добавьте `it: 'it.json'` в `LOCALE_TRANSLATION_FILES`, а итальянские тексты — в `FOOTNOTE_LABELS` и `FOOTNOTE_BACK_LABELS`.
3. **Переведите интерфейс**: зарегистрируйте код, название, сокращение и каталог в `SUPPORTED_LANGUAGES` в `src/utils/i18n.ts` и заполните все ключи `UI_TRANSLATIONS`, включая поиск, Pagefind и сообщения 404.
4. **Переведите весь контент**: создайте `src/content/docs/it/index.mdx` и полные переводы в `src/content/docs/it/canvas/`, соответствующие файлам языка по умолчанию один к одному. Сохраните ключи Frontmatter, уровни заголовков и структуру блоков кода. Китайский текст-заглушка не считается переводом.
5. **Подготовьте локализованные изображения**: положите одноимённые файлы в `public/images/canvas/it/`. Только действительно общие изображения вносите в `SHARED_ALLOWLIST` в `scripts/check-localized-images.mjs`. Для генератора схем добавьте `scripts/diagram-i18n/it.mjs` и запись в `LOCALES` в `scripts/generate-diagram-locales.mjs`; для инструмента снимков обновите `LOCALES` и `SEARCH_WORDS` в `scripts/capture-ui-shots.mjs`.
6. **Расширьте проверки**: добавьте `it` в `locales` и `LATIN` в `scripts/audit-i18n.mjs`, в `LOCALES` в `scripts/check-anchors.mjs` и в `LOCALE_DIRS` в `scripts/check-localized-images.mjs`. Добавьте `['it', 'it']` в соответствие языков и каталогов `LANG_DIRS` в `scripts/check-links.mjs`. `scripts/check-images.mjs` рекурсивно обходит все каталоги изображений и не требует регистрации языка.
7. **Сначала проверьте исходники и изображения**: из корня репозитория выполните `node scripts/audit-i18n.mjs` и `node scripts/check-images.mjs`. Вторая команда проверяет только сигнатуру PNG и минимальный размер, а не перевод текста и вёрстку изображения.
8. **Выполните полную проверку до публикации**: `pnpm run verify` собирает сайт и проверяет ссылки на локализованные изображения, ссылки, якоря и языковые метаданные. Через `pnpm run preview` проверьте главную страницу, статьи, смену языка и поиск на новом языке. Исправьте все ошибки, не удаляя проверки ради публикации.

## Для разработчиков: как добавить или изменить интерфейсные строки

Добавляя новый элемент интерфейса, дополните словарь `UI_TRANSLATIONS` в `src/utils/i18n.ts`:

```typescript
// Путь к файлу: src/utils/i18n.ts
// Словарь организован в два уровня «язык → ключ строки», в том же порядке, в котором его читает getTranslation
export const UI_TRANSLATIONS: Record<string, Record<string, string>> = {
  // Шаг 1: добавьте строки в язык по умолчанию zh-CN (при их отсутствии интерфейс показывает имя ключа)
  'zh-CN': {
    'nav.plugins': '插件生态',
    // ...остальные существующие строки
  },
  // Шаг 2: добавьте перевод с тем же ключом для других языков; языки без перевода автоматически откатываются к китайскому
  en: {
    'nav.plugins': 'Plugins',
  },
  ja: {
    'nav.plugins': 'プラグイン',
  },
};
```

Затем вызовите `getTranslation` в компоненте, передав текущий язык:

```astro
---
import { getLangFromLocale, getTranslation, localizedHref } from '../../utils/i18n';
const lang = getLangFromLocale(Astro.currentLocale);
---

<a href={localizedHref('/plugins/', lang)}>{getTranslation('nav.plugins', lang)}</a>
```

Интерфейсные строки при сборке рендерятся как статический текст на соответствующем языке, без накладных расходов во время выполнения.

В примере показаны только три языковые ветви. Новые строки нужно перевести на каждый зарегистрированный язык; возврат к китайскому — защита, а не завершённый перевод.
