Здесь описано развёртывание статической документации на **Cloudflare Pages** по скриптам репозитория. Снимки — существующие примеры, а не отчёты о развёртывании или тестах этой кандидатной версии. При отличиях используйте текущую консоль. Успех проверок и публикации нужно подтверждать реальными журналами и статусами, а не этой инструкцией.

---

## Подготовка

### Что вам понадобится

| Пункт | Пояснение |
| :--- | :--- |
| **Аккаунт Cloudflare** | Бесплатная регистрация на [dash.cloudflare.com](https://dash.cloudflare.com/); для сервиса Pages платный тариф не требуется |
| **Успешная локальная сборка** | Сначала проверьте, что `pnpm run verify` отрабатывает и каталог `dist/` корректно создаётся; см. [Быстрый старт](/canvas/deployment/) |
| **Node.js + pnpm** | Команды развёртывания зависят от локальной среды разработки; требования к версиям — как в главе «Быстрый старт» |

### Как выбрать один из двух способов развёртывания

![Локальная загрузка Wrangler и сборка через интеграцию Git](/images/canvas/docs-deploy-compare.svg)

*Рисунок: слева локальная сборка и загрузка Wrangler, справа облачная сборка через Git. Схема не подтверждает тестирование этих путей в ходе этой правки.*

| Параметр сравнения | Способ 1: прямая загрузка из командной строки | Способ 2: автоматическая сборка из Git |
| :--- | :--- | :--- |
| Как выполняется | Локальный запуск `pnpm run deploy` | Запускается автоматически при отправке кода на GitHub |
| Порог входа | Низкий, две команды | Средний, требуется однократная настройка в консоли |
| Подходящие сценарии | Первый запуск, обслуживание одним человеком, быстрые обновления | Совместная работа нескольких людей, желание «закоммитил — значит опубликовано» |
| Проверки | Полный verify до загрузки | Настройте полный verify в облачной команде сборки |

:::tip
При создании выберите Direct Upload или интеграцию Git. Не считайте, что проект прямой загрузки можно сразу преобразовать в Git-проект; при смене пути создайте подходящий проект. Срочная загрузка Wrangler также не должна обходить проверки.
:::

:::tip[Совсем не хотите вводить команды?]
На странице [Быстрый старт](/canvas/deployment/) есть кнопки развёртывания в один клик для Cloudflare, Vercel и Netlify: нажмите, авторизуйте аккаунт, подтвердите настройки — и сайт документации опубликуется в вашем облачном аккаунте; подробнее в разделе [Развёртывание в один клик](/canvas/deployment/#развёртывание-в-один-клик-одно-нажатие-кнопки-и-сайт-в-сети). Кнопка Cloudflare использует статический хостинг Workers, это отдельный путь, не совпадающий со способом Pages, описанным на этой странице; для статического сайта документации качество доступа у них одинаковое — выберите любой один путь.
:::

## Способ 1: прямая загрузка из локальной командной строки (рекомендуется для первого раза)

Сборка выполняется локально, затем Wrangler загружает файлы. `pnpm run deploy` предназначен для проекта сопровождающих `epocanvas-docs`, а не для любого fork без настройки.

### Шаг 1: вход в аккаунт Cloudflare

В проекте уже предустановлен Wrangler (официальный инструмент командной строки Cloudflare); при первом использовании нужно авторизоваться через браузер:

```bash
pnpm exec wrangler login
```

После запуска в терминале появится сообщение `Opening a link in your default browser...`, браузер откроет страницу авторизации Cloudflare; после нажатия **Allow** терминал сообщит об успешном входе. Проверить состояние входа можно командой:

```bash
pnpm exec wrangler whoami
```

:::caution
Нужны действующая авторизация или токен Cloudflare с правами. При ошибке проверьте `wrangler whoami`, аккаунт и права проекта. Текст ошибки может зависеть от версии.
:::

### Шаг 2: сборка и загрузка одной командой

В `scripts/verify-release.mjs` проекта предустановлена команда публикации одной кнопкой:

Авторизуйтесь через `pnpm exec wrangler login`. `scripts/verify-release.mjs` требует ветку `main`, чистое дерево с учётом неотслеживаемых файлов, upstream `origin/main` и HEAD, равный реальному удалённому коммиту. `pnpm run deploy` выполняет полный `pnpm run verify`, повторно проверяет Git и вызывает Wrangler. Перед повторным использованием настройте собственный целевой проект в скрипте.

```bash
pnpm run deploy
```

`pnpm run deploy` проверяет конфигурацию, типы Astro, сборку, тесты и содержимое/артефакты до загрузки. Для одних предварительных условий используйте команду ниже. Она читает удалённые Git-ссылки, но не выполняет полный verify, сборку или загрузку. Успешный dry-run не означает успешные тесты.

```bash
pnpm run deploy --dry-run
```

Wrangler выводит URL после успешной загрузки. Скрипт задаёт `--project-name epocanvas-docs --branch main`; проверьте наличие проекта в аккаунте и настройку рабочей ветки.

### Шаг 3: найдите свой проект в консоли

Откройте [dash.cloudflare.com](https://dash.cloudflare.com/), в меню слева нажмите **Compute (Workers & Pages)** — откроется список проектов. На рисунке ниже отмечены три ключевых места:

![Список проектов Workers & Pages в консоли Cloudflare с отметками: вход в меню слева, кнопка Create application и проект epocanvas-docs](/images/canvas/deploy/cf-01-projects-list.png)

*Рисунок: список проектов Workers & Pages. ① переход в Workers & Pages через меню слева; ② кнопка Create application для создания нового проекта; ③ наш проект `epocanvas-docs` с доменом доступа `epocanvas-docs.pages.dev` и временем последнего развёртывания.*

Нажмите на имя проекта, чтобы открыть его страницу; вкладка **Deployments** показывает полную историю развёртываний:

![Страница истории развёртываний проекта epocanvas-docs с отметками производственного домена, записей развёртываний и их статусов](/images/canvas/deploy/cf-02-deployments.png)

*Рисунок: страница истории развёртываний. ① имя проекта; ② вкладка Deployments; ③ к производственному домену привязаны одновременно `docs.epocanvas.com` (собственный домен) и `epocanvas-docs.pages.dev` (домен по умолчанию); ④ у каждой записи развёртывания отмечены ветка и информация о коммите; ⑤ статус и время развёртывания.*

:::note
Запись создаётся только после успешной загрузки. В Deployments проверьте статус, ветку, коммит и домен. Отказ команды или ошибка проверки не обновляют сайт.
:::

Откройте вкладку **Settings**, чтобы увидеть отличие проекта с прямой загрузкой от проекта на Git:

![Страница конфигурации сборки Settings проекта epocanvas-docs, где в поле Git repository показано, что репозиторий не подключён](/images/canvas/deploy/cf-03-settings.png)

*Рисунок: вкладка Settings. ① вход в Settings; ② в поле Git repository показано Connect (не подключён) — проекту с прямой загрузкой не нужна конфигурация сборки из Git, вся сборка выполняется локально.*

:::tip
Прямая загрузка не зависит от очереди облачной сборки. Компьютеру нужны подходящие Node, pnpm, Git и учётные данные; использовать один и тот же компьютер необязательно.
:::

## Способ 2: автоматическая сборка с подключением репозитория Git (необязательно)

Для сборок по push создайте Pages-проект с Git-интеграцией и подключите репозиторий. Далее дана инструкция настройки, а не подтверждение включения или тестирования этого пути сейчас.

### Шаг 1: переход к созданию проекта

На странице списка проектов Workers & Pages нажмите кнопку **Create application** в правом верхнем углу (отметка ② на рисунке из [шага 3 способа 1](#шаг-3-найдите-свой-проект-в-консоли)) и выберите вкладку **Pages**.

### Шаг 2: подключение репозитория Git

1. На экране создания выберите **Connect to Git**;
2. Авторизуйте доступ Cloudflare к вашему аккаунту GitHub;
3. В списке репозиториев выберите репозиторий документации `epocanvas-docs`;
4. Нажмите **Начать настройку**.

### Шаг 3: заполнение конфигурации сборки

В разделе «Настройка сборки и развёртывания» укажите следующую конфигурацию:

| Параметр | Значение |
| :--- | :--- |
| Пресет фреймворка | `Astro` |
| Команда сборки | `pnpm install --frozen-lockfile && pnpm run verify` |
| Каталог результата | `dist` |
| Node.js | `22.23.4`, как в `.node-version` |
| pnpm | `10.34.5`, как в `packageManager` |

### Шаг 4: проверка автоматической сборки

Проверьте Node и pnpm в облаке, нажмите **Сохранить и развернуть** и изучите журнал Deployments. Установка, полная проверка и загрузка должны пройти успешно. Последующие push зависят от рабочей ветки и настроек автоматизации. Успех GitHub CI сам по себе не публикует Pages.

:::caution
На странице Settings проекта с интеграцией Git появляется дополнительный блок конфигурации сборки (пресет фреймворка, команда сборки и т.д.) — интерфейс отличается от [проекта с прямой загрузкой](#конфигурация-сборки-проекта-с-прямой-загрузкой). Если вы не находите конфигурацию сборки в Settings, значит текущий проект использует прямую загрузку, и это нормальная ситуация.
:::

## Привязка собственного домена

Cloudflare предоставляет `<project-name>.pages.dev`; можно подключить свой домен. Ниже приведены примеры. Сроки DNS и сертификатов определяются реальным состоянием.

### Шаг 1: открытие настроек собственного домена

На странице проекта откройте вкладку **Custom domains** и нажмите **Set up a custom domain**:

![Страница собственного домена проекта epocanvas-docs, где docs.epocanvas.com уже привязан и SSL активен](/images/canvas/deploy/cf-04-domains.png)

*Рисунок: вкладка Custom domains. ① вход во вкладку; ② кнопка Set up a custom domain; ③ привязанный `docs.epocanvas.com` со статусом Active и включённым SSL.*

### Шаг 2: добавление домена и ожидание активации

1. Нажмите **Set up a custom domain** и введите свой поддомен (например, `docs.epocanvas.com`);
2. Если DNS домена уже обслуживается в Cloudflare, CNAME-запись добавится автоматически; для домена, обслуживаемого в другом месте, нужно вручную добавить CNAME-запись, указывающую на `<имя проекта>.pages.dev`;
3. Дождитесь проверки DNS и выдачи сертификата, затем проверьте домен со статусом **Active**. Фиксированное число минут не гарантирует завершения.

HTTPS-сертификаты Cloudflare выдаёт и продлевает автоматически; ручное оформление или настройка не требуются.

## Проверка результата развёртывания

### Проверка HTTP-статуса из командной строки

```bash
curl -sI https://epocanvas-docs.pages.dev
```

Пример ответа (дата и статус зависят от фактического запроса):

```text
HTTP/2 200
date: Fri, 11 Sep 2026 15:32:39 GMT
content-type: text/html; charset=utf-8
```

`200` подтверждает только успешный ответ этого URL, но не переводы, ресурсы, поиск или актуальность содержимого. Продолжите проверки ниже на обоих доменах.

### Поэтапная проверка в браузере

| Проверка | Ожидаемый результат |
| :--- | :--- |
| Главная и любая страница документации открываются | Страница отрисовывается полностью, без белого экрана |
| Свежие изменения вступили в силу | Только что отредактированный раздел виден на опубликованном сайте |
| Поиск по всему сайту через `Ctrl+K` | Находятся новейшие статьи (индекс создаётся при сборке) |
| Переключение светлой/тёмной темы | Переключается нормально и сохраняется после обновления страницы |

## Частые проблемы при развёртывании

### После развёртывания содержимое сайта не обновилось?

Сначала исключите кэш жёстким обновлением браузера (`Ctrl+F5` / `Cmd+Shift+R`); если всё ещё не обновляется, на странице Deployments консоли проверьте время последней записи, а затем сравните с доменом предпросмотра развёртывания через `curl -sI`.

### На собственном домене ошибка SSL handshake (Error 525)?

Проверьте в Custom domains валидацию и сертификат, затем DNS, прокси и подробности ошибки. Не ограничивайтесь ожиданием нескольких минут; сравните с `pages.dev`.

### Команда `pnpm run deploy` выдаёт ошибку `Project not found`?

Сначала выполните `pnpm exec wrangler whoami`, чтобы убедиться, что вы вошли; затем сверьте `--project-name` в `scripts/verify-release.mjs` с именем проекта в консоли.

Остальные пункты диагностики — в разделе [Частые вопросы и устранение неполадок](/canvas/troubleshooting/).
