Документация пишется для людей, но сначала её нужно найти, а страницы — открываться быстро. **EpoCanvas Docs** уже на уровне сборки включает готовый к использованию набор возможностей SEO и механизмов производительности. На этой странице объясняется, что именно входит в этот набор, как это проверить и что остаётся сделать после запуска сайта.

## Встроенные возможности SEO

Все перечисленные ниже возможности автоматически работают на этапе сборки и не требуют дополнительной настройки:

| Возможность | Как реализована | Как проверить |
| :--- | :--- | :--- |
| Заголовок страницы | `<title>Заголовок статьи \| EpoCanvas Docs</title>`, берётся из Frontmatter | Посмотреть исходный код страницы или вкладку браузера |
| Описание страницы | `<meta name="description">`, берётся из `description` во Frontmatter | Посмотреть исходный код |
| Теги Open Graph | `og:title`, `og:type`, `og:url`, `og:locale`, `og:description`; при репосте в социальные сети показывается карточка | Вставить ссылку в мессенджер и посмотреть предпросмотр |
| Каноническая ссылка | `<link rel="canonical">` генерируется автоматически для каждой страницы и указывает на основной домен | Посмотреть исходный код |
| Sitemap | `sitemap-index.xml` генерируется автоматически при сборке | Открыть `/sitemap-index.xml` |
| robots.txt | В проект входит `public/robots.txt`, разрешающий всех роботов и объявляющий расположение sitemap | Открыть `/robots.txt` |

:::tip
`title` и `description` во Frontmatter — основной материал, который показывают поисковые системы. При написании документов обязательно заполняйте краткое и точное `description`: это самая важная одиночная SEO-оптимизация.
:::

### Canonical и зеркальный домен

Основной домен сайта — `docs.epocanvas.com`, конфигурация `<site>` соответствует ему, и canonical, и `og:url` каждой страницы указывают на основной домен. Даже если контент одновременно доступен через зеркало `epocanvas-docs.pages.dev`, поисковые системы сводят вес к основному домену и не считают это дублированным контентом.

## Механизмы производительности

### Чисто статический вывод, без рантайма фреймворков

Результат сборки — чистый HTML + CSS. Навигация по страницам, чтение и подсветка оглавления при прокрутке не требуют загрузки каких-либо фронтенд-фреймворков (объём рантаймов React/Vue и т.п. равен нулю); лишь интерактивные компоненты — поиск, переключение темы, переключение языка — подгружают по необходимости немного скриптов. Первый экран отрисовывается без ожидания JavaScript, и на слабой сети и маломощных устройствах всё работает так же плавно.

### Размер изображений контролируется в источнике

На этом сайте обработка изображений на этапе сборки отключена: в `astro.config.mjs` параметр `image.service` установлен в `passthroughImageService()`, поэтому файлы из `public/` копируются в `dist/` без изменений — без сжатия и без изменения размера. sharp сознательно не используется: в изолированной структуре каталогов pnpm его нативная зависимость не разрешается, а при пустом кэше (CI, первая сборка) сборка прерывается ошибкой `MissingSharp`. Размер контролируется до коммита: снимки интерфейса шириной 1440 пикселей, сжатые заранее, а схемы архитектуры — только в SVG.

### Загрузка поискового индекса по мере необходимости

Pagefind на этапе `pnpm run build` создаёт сильно сжатые фрагменты индекса. Читатель при открытии страницы не загружает никакого индекса; только при реальном использовании поиска по всему сайту браузер по ключевым словам подтягивает соответствующие фрагменты (от нескольких КБ до десятков КБ), не замедляя первый экран.

### Как проверить производительность

1. Откройте панель **Network** в инструментах разработчика браузера, обновите страницу и посмотрите объём передачи для первого экрана;
2. Запустите аудит **Lighthouse** в окне Chrome в режиме инкогнито (категория Performance) и проверьте оценки;
3. С помощью `curl -sI https://docs.epocanvas.com` проверьте, работают ли CDN-стратегии кэширования, такие как `Cache-Control`, в заголовках ответа.

## Три дела, которые рекомендуется сделать после запуска

После завершения развёртывания (см. [Развёртывание на Cloudflare Pages](/canvas/cloudflare/)) рекомендуется выполнить по порядку следующее:

### 1. Отправьте Sitemap в Google Search Console

1. Откройте [Google Search Console](https://search.google.com/search-console) и добавьте ресурс `docs.epocanvas.com`;
2. Подтвердите владение доменом через DNS TXT-запись по подсказкам сервиса (если домен обслуживается в Cloudflare, это занимает несколько минут);
3. В разделе «Файлы Sitemap» слева отправьте `https://docs.epocanvas.com/sitemap-index.xml`.

### 2. Проверьте индексацию

Через неделю после запуска выполните поиск в Google по запросу `site:docs.epocanvas.com` и убедитесь, что статьи проиндексированы; в отчёте «Страницы» Search Console проверьте, совпадает ли количество проиндексированных страниц с количеством документов.

### 3. Периодически проверяйте битые ссылки

После переработки документации и переименования путей старые ссылки, размещённые вне сайта, могут перестать работать. В отчёте «Страницы» Search Console можно смотреть записи «Не найдено (404)» и добавлять переадресацию для часто посещаемых устаревших путей в таблице `redirects` в `astro.config.mjs`.

:::caution
Зеркальный домен `epocanvas-docs.pages.dev` служит только резервным входом для доступа; canonical уже гарантирует, что поисковые системы индексируют только основной домен. Не распространяйте зеркальный адрес вне сайта, чтобы читатели не добавили в закладки домен, который вы не контролируете.
:::
