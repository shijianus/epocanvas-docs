**EpoCanvas Docs** はページ内検索とサイト全体検索を備えています。表示幅が `64rem` 以上の場合はトップバーにページ内入力欄を表示し、`64rem` 未満ではサイト全体検索ボタンだけを表示します。サイト全体検索は Pagefind の静的インデックスを使い、検索バックエンドは不要です。

---

## 2 つの検索の使い分け

| シーン | 使う検索 | 操作方法 |
| :--- | :--- | :--- |
| 内容が**現在の記事**にある | ページ内検索 | `64rem` 以上ではトップバーに入力。狭い画面ではブラウザーのページ内検索を使用 |
| **どの記事**にあるか不明 | サイト全体検索 | トップバーの検索ボタン、または `Ctrl + K`（Mac は `Cmd + K`） |

---

## ページ内検索：トップバーの検索ボックス

以下は表示幅が `64rem` 以上の場合の操作です。トップバーの入力欄にキーワードを入力します。それ未満では入力欄、件数、移動ボタンは非表示となり、サイト全体検索を開く虫眼鏡ボタンだけが残ります。狭い画面で現在の記事を探すにはブラウザーのページ内検索を使ってください。

![トップバーのページ内検索の注釈図：① 入力ボックス ② マッチ数 ③ 前後への移動 ④ クリア ⑤ ページ内ハイライト](/images/canvas/ui-inpage-search.png)

*図：既存のページ内検索の参考画像です。現在の件数、前後移動、クリアの操作欄は入力欄の下に表示され、欄内ではありません。狭い画面では非表示です。位置、件数、レイアウトが異なる場合は実際の画面を優先してください。*

### キーワードの入力

語句や `pnpm`、`astro.config.mjs` などのコードを入力できます。本文の表示中の一致文字列がハイライトされ、最初の一致へ移動します。ナビゲーションや非表示の内容は対象外です。

### マッチ結果間の移動

- 入力欄にフォーカスがある状態で <kbd>Enter</kbd>、または下向き矢印ボタン：次の一致へ移動。
- 入力欄にフォーカスがある状態で <kbd>Shift + Enter</kbd>、または上向き矢印ボタン：前の一致へ移動。
- 入力欄の下に `N/M`（例：`3/9`）で現在の一致番号と総数を表示します。

### 検索のクリアとページの復元

入力欄で <kbd>Esc</kbd> を押すか `×` クリアボタンをクリックすると、検索語とハイライトを消去します。

## サイト全体検索：Ctrl+K ダイアログ

<kbd>Ctrl</kbd> + <kbd>K</kbd>（Mac は <kbd>Cmd</kbd> + <kbd>K</kbd>）、またはトップバーの検索ボタンで開きます。広い画面ではキーのバッジ、`64rem` 未満では虫眼鏡アイコンです。どちらもサイト全体検索を開き、ページ内入力ではありません。

![サイト全体検索ダイアログの注釈図：① 起動バッジ ② 検索入力ボックス ③ 結果リスト ④ ショートカットキー欄](/images/canvas/ui-search-modal.png)

*図：入力欄と結果を示す既存の参考画像です。ボタン位置やキーの案内が現状と異なる場合は実際の画面と以下の説明を優先してください。現在は Tab でリンクにフォーカスを移します。狭い画面では下部の案内が非表示になる場合があります。*

### キーワードの入力

現在のページの言語の語句や `pnpm`、`astro.config.mjs` を入力します。Pagefind は関連度で並べるため、タイトル一致が必ず先頭になるわけではありません。

### 結果リストの閲覧

結果は文書ごとにタイトル、一致箇所の抜粋、利用可能な節の子結果を表示します。タイトルと子結果はリンクです。タイトルは文書を開き、節リンクはアンカーへ移動します。タイトルに展開・折りたたみ機能はありません。

### キーボードだけで操作を完結

- <kbd>Tab</kbd> / <kbd>Shift + Tab</kbd>：入力欄、ボタン、結果リンク間のフォーカスを順に移動。
- 結果リンクにフォーカスがある状態で <kbd>Enter</kbd>：リンクを開く。節リンクはアンカーへ移動。
- <kbd>Esc</kbd>：ダイアログを閉じる。

現在の Pagefind UI は <kbd>↑</kbd> / <kbd>↓</kbd> による結果選択や、文書タイトルをクリックして一致箇所を展開する操作には対応していません。

## なぜ検索が速いのか

![EpoCanvas Docs の 2 モード検索の仕組み比較図：左はトップバーのページ内検索（DOM 走査によるハイライト、リアルタイムカウントとスムーズスクロール）、右はサイト全体検索ダイアログ（Ctrl+K で起動、Pagefind WASM のメモリ上の転置インデックスによる即時マッチング）](/images/canvas/docs-search-flow.svg)

*図：2 モード検索の動作の比較。左はトップバーによるページ内のキーワードの素早い位置特定、右は Pagefind WASM に基づくサイト全体の静的インデックス検索で、どちらも完全にブラウザー内で動作します。*

多くのサイトのドキュメント検索は、リクエストをリモートサーバーのデータベースへ送って照会するため、ネットワークが不安定なときはぐるぐる待たされるばかりです。

EpoCanvas Docs では **Pagefind** のローカル静的検索方式を採用しています。

1. **ビルド時にインデックスを抽出**：`pnpm run build` を実行すると、システムが各ドキュメントの内容を自動的に取り込み、圧縮済みの静的インデックス分割ファイル一式を生成します。
2. **必要な索引を取得**：検索プログラムとインデックスの断片をサイトから読み込みます。初回やキャッシュがない場合はネットワーク通信が発生します。
3. **ブラウザー内で照合**：索引の読み込み後に照合と順位付けを実行します。イントラネットでも検索用ファイルの配信が必要で、初回アクセスから通信不要という意味ではありません。

## 検索を便利に使うコツ

- **語句の分割**：より絞り込んだ結果を得たい場合は、複数の語をスペースで区切って入力します（例：`Cloudflare ドメイン` と入力）。
- **具体的な語を使う**：タイトルや節名で絞り込めますが、表示順は Pagefind の関連度評価によります。
- **開発モードの制限**：サイト全体のインデックスはビルド時にのみ生成され、`pnpm run dev` の開発サーバーでは `Ctrl+K` ダイアログがインデックスを読み込まないため、サイト全体検索は使用できません。検索を確認するには `pnpm run build` を実行し、`pnpm run preview` でビルド結果を開いてください。ページ内検索はこの制限を受けません。
