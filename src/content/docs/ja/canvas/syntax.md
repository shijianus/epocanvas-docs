## 1. 4 種類のカラー吹き出し（コールアウト）

吹き出し（コールアウト）はコロン 3 つの構文を使います：`:::タイプ` で始め、`:::` で終え、間に内容を書きます。本サイトは Starlight をベースにしており、**note、tip、caution、danger** の 4 種類に対応しています。

### 構文と実際の表示の対応

:::note
**note（補足説明）**：背景知識の紹介、設計の詳細の補足、前提となる依存関係の案内に使います。
:::

:::tip
**tip（実用的なコツ）**：操作効率を上げる小ワザやベストプラクティスを共有するのに使います。
:::

:::caution
**caution（注意警告）**：起こりうる互換性の競合、潜在的なエラー、特に注意が必要な操作を伝えます。
:::

:::danger
**danger（危険度の高い警告）**：データ損失、本番環境の上書き、不可逆な操作にかかわる最も高いレベルの警告です。
:::

### 吹き出しの中には任意の内容を入れられる

吹き出しの中でも、リスト、コードブロック、テーブルなどの構文をそのまま使えます。

:::tip[インストールの高速化]
pnpm で依存関係をインストールすると npm よりはるかに速いです。

```bash
npm install -g pnpm
```
:::

:::caution
よくある 2 つの無効な書き方です。避けてください：

- GitHub 風の `> [!NOTE]` 引用ブロック構文は非対応で、そのまま普通の引用ブロックとして表示されます。
- `:::important` と `:::warning` は**本サイトが対応するタイプではありません**。エラーにはなりませんが、黙って通常の段落としてレンダリングされ、吹き出しのスタイルは一切付きません。

GitHub のドキュメントから移行するときは、`> [!NOTE]` を `:::note` へ、`> [!WARNING]` を `:::caution` へ、`> [!CAUTION]` を `:::danger` へ書き換えてください。
:::

## 2. コードブロックの高度な整形

### 2.1 ファイル名タイトルと指定行のハイライト

コードフェンスの最初の行に `title="ファイルパス"` を書き、`{行番号}` でポイントとなる行をハイライトします。

````markdown
```typescript title="src/config/site.ts" {2}
export const siteConfig = {
  name: 'EpoCanvas Docs', // この行がハイライト背景で強調されます
  version: '1.2.0',
};
```
````

**レンダリング結果：**

```typescript title="src/config/site.ts" {2}
export const siteConfig = {
  name: 'EpoCanvas Docs',
  version: '1.2.0',
};
```

### 2.2 差分コードの対比 (diff)

設定の更新やコードのリファクタリングを見せるときは、`diff` 言語を使うと変更点がひと目で分かります。`-` で始まる行は削除、`+` で始まる行は追加として表示されます。

````markdown
```diff
  export default defineConfig({
-   site: 'http://localhost:3000',
+   site: 'https://docs.epocanvas.com',
  });
```
````

**レンダリング結果：**

```diff
  export default defineConfig({
-   site: 'http://localhost:3000',
+   site: 'https://docs.epocanvas.com',
  });
```

### 2.3 ターミナルコマンド

`bash`、`sh`、`powershell` などのターミナル言語は、ターミナル風の暗い枠でレンダリングされます。

```bash
pnpm run build
```

## 3. 図表はどう挿入する？

現在のバージョンでは **Mermaid などのテキスト図表のレンダリングは組み込まれていません**。` ```mermaid ` フェンスをそのまま書いても、通常のコードブロックとしてソースが表示されるだけで、図は生成されません。

おすすめの方法は、[mermaid.live](https://mermaid.live) などのツールで図を書いて **SVG ベクター画像**として書き出し、`public/images/canvas/` に保存してから画像の構文で挿入することです。本サイトのアーキテクチャ図や言語切り替えのフロー図も、この方法で作成しています。

![システムアーキテクチャの模式図](/images/canvas/docs-architecture.svg)

*図：SVG 画像として挿入したアーキテクチャの模式図。どの倍率で拡大してもぼやけません。*

Mermaid のソースをどうしても直接レンダリングしたい場合は、プロジェクトに追加のレンダリングプラグイン（例：`rehype-mermaid`）を導入する必要があります。これはカスタマイズの範疇なので、メンテナンスコストを見極めてから導入してください。

## 4. その他の便利な整形

- インラインコード：`pnpm run dev`。テーマカラーの等幅フォントでレンダリングされます。
- キーボードのキー：<kbd>Ctrl</kbd> + <kbd>K</kbd>。キーキャップ風のスタイルでレンダリングされます。
- タスクリスト：

```markdown
- [x] シンタックスハイライト対応
- [x] ワンクリックコピー対応
- [ ] Mermaid レンダリングの組み込み（計画中）
```

チェック状態付きのリスト項目としてレンダリングされます。

### 4.1 脚注

出典や補足説明を付けたいときは、GFM の脚注構文を使えます。

````markdown
静的インデックスは Pagefind がビルド時に生成します[^pagefind]。

[^pagefind]: [Pagefind 公式ドキュメント](https://pagefind.app/) — 静的サイト向けのローカル検索ライブラリ。
````

**レンダリング結果：** 本文の末尾には番号付きの上付きジャンプマーク[^pagefind-demo]が現れ、クリックするとページ下部の脚注リストへスムーズに移動します。

[^pagefind-demo]: これがこのページの下部にレンダリングされた脚注の本体です。

吹き出し（コールアウト）、コードの注記、模式図を上手に使い分けると、技術ドキュメントの読みやすさと専門性が大きく向上します。構文の取り決めの全体は **[レンダリングルールの詳細](/canvas/rendering/)** を参照してください。
