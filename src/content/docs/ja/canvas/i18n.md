**EpoCanvas Docs** にはコンテンツレベルの多言語対応が組み込まれています。ナビゲーションバー、サイドバー、検索の案内などの UI 文字列も、各ドキュメントの本文も、10 言語それぞれの独立したバージョンが用意されています。読者がページ右上で言語を選ぶと、同じ記事の対象言語版へ移動し、本文と UI がまとめて切り替わります。

---

## 対応言語の一覧

サイトは現在 10 言語を提供しており、そのうち簡体字中国語がデフォルト言語です。

| 言語 | 言語名称 | URL プレフィックス | UI 略称 |
| :--- | :--- | :--- | :--- |
| 简体中文 | **簡体字中国語**（デフォルト） | プレフィックスなし | ZH |
| 繁體中文 | 繁体字中国語 | `/zh-tw/` | TW |
| English | 英語 | `/en/` | EN |
| 日本語 | 日本語 | `/ja/` | JA |
| 한국어 | 韓国語 | `/ko/` | KO |
| Español | スペイン語 | `/es/` | ES |
| Français | フランス語 | `/fr/` | FR |
| Deutsch | ドイツ語 | `/de/` | DE |
| Русский | ロシア語 | `/ru/` | RU |
| Português | ポルトガル語 | `/pt/` | PT |

言語一覧は `src/utils/i18n.ts` の `SUPPORTED_LANGUAGES` にあります。`astro.config.mjs` の `locales` はルートを登録し、`LOCALE_DIRS` はデフォルト以外の言語ディレクトリを識別します。言語追加時は `locales` だけでなく、翻訳辞書と検証スクリプトも更新します。

## 言語の切り替え方法

1. ページ上部ナビゲーションバーの右側にある言語ボタンを探します（現在の言語の略称、例：`ZH` が表示されています）。
2. ボタンをクリックすると、ドロップダウンメニューに 10 言語すべてが表示されます。
3. 対象の言語（例：`English` や `日本語`）をクリックします。
4. ブラウザーが現在の記事の対象言語版へ移動し、ナビゲーション、サイドバー、目次、本文がまとめて対象言語に変わります。

## URL の規則

各言語のページには独立した URL プレフィックスがあり、同じ記事は言語が違ってもプレフィックスしか違いません。

```text
/canvas/i18n/          → 簡体字中国語（デフォルト言語、プレフィックスなし）
/en/canvas/i18n/       → 英語
/ja/canvas/i18n/       → 日本語
/zh-tw/canvas/i18n/    → 繁体字中国語
```

- 言語情報は URL に直接エンコードされているため、切り替え後のページをそのままブックマークや共有でき、検索エンジンも言語ごとに別々にインデックスできます。
- ページ内のサイト内リンク（ナビゲーション、サイドバー、本文中のおすすめリンク）にはすべて現在の言語のプレフィックスが自動的に付くため、ある言語で読み続けている間に簡体字中国語のページへ戻されることはありません。
- 各言語版はビルド時に生成される独立した静的ページで、ページの `<html lang>` 属性は言語と一致するため、スクリーンリーダーや翻訳ツールが正しく認識できます。

## 翻訳が不足している場合

翻訳がない場合、Starlight はデフォルトの簡体字中国語本文を使って対象言語のルートを生成できます。これは技術的なフォールバックであり、このプロジェクトで認める公開方針ではありません。本文が中国語でも、ページの言語宣言は対象言語のままになる場合があります。

このプロジェクトでは、トップページと全記事を 10 言語で揃えて保守します。`node scripts/audit-i18n.mjs` は不足・余分なページ、Frontmatter、見出し、コードフェンスの構造を検証します。翻訳不足は非ゼロ終了コードとなり、`pnpm run verify` と CI を停止させます。追加・変更した内容は全言語に反映してから公開し、中国語版だけを先に公開して後で翻訳する運用はできません。`pnpm run build` の成功だけでは公開前検証の合格にはなりません。

## 実装の仕組み

多言語機能は Astro と Starlight の国際化の仕組みによって実現されており、ビルドの流れは次のとおりです。

1. **コンテンツディレクトリを言語別に分ける**：デフォルト言語のドキュメントは `src/content/docs/`（簡体字中国語）に置き、他の言語は `src/content/docs/<言語>/` の下に置きます。ディレクトリ構造は簡体字中国語版と完全に対応しており、たとえば英語版の「多言語対応と言語切り替え」は `src/content/docs/en/canvas/i18n.md` です。
2. **ビルド時に全言語のページを生成**：`astro build` は `astro.config.mjs` の `locales` 設定を読み込み、言語ごとに一式の完全な静的ページを生成します。
3. **UI 文字列を言語別にレンダリング**：トップバーのナビゲーション、検索の案内、目次の見出しなどの UI 文字列は、各コンポーネントが `getTranslation(key, lang)` を呼び出してビルド時に対応言語を直接出力します。ページ内に実行時の差し替えスクリプトはありません。
4. **本文内の内部リンクを自動ローカライズ**：ビルドパイプラインの `rehypeLocalizeInternalLinks` プラグインが、翻訳本文中の `/canvas/xxx` 内部リンクに現在の言語のプレフィックスを自動的に付けます。
5. **全文検索を言語別に分離**：Pagefind は言語ごとに独立したインデックスを構築し、英語のページでの検索は英語の結果だけを返します。
6. **本文画像のローカライズと検証**：`rehypeLocalizeDiagramImages` は同名の翻訳画像がある場合に `/images/canvas/<ファイル名>` を `/images/canvas/<言語>/<ファイル名>` に書き換え、なければ元画像を残します。ただし公開前の `check-localized-images.mjs` は各言語の画像を必須とし、`SHARED_ALLOWLIST` に登録した第三者 UI のスクリーンショットなど、本当に共用する画像だけを例外とします。元画像へのフォールバックで翻訳を省略できるわけではありません。
7. **吹き出しと脚注もページの言語に追従**：`rehypeLocalizeAsides` と `rehypeLocalizeFootnotes` はソースファイルのある言語ディレクトリに基づき吹き出しタイトルと脚注文言を書き換えます。Starlight は remark 段階で絶対パスから言語を推定しますが、ローカルビルドでは相対パスが渡されるため、この処理がないとすべて中国語にフォールバックします；
8. **hreflang と 404 ページ**：`hreflangXDefault()` はビルド後に各ページへ `hreflang="x-default"` を 1 本追加し、簡体字中国語版を指します。`src/pages/404.astro` は同じ辞書を使い、ブラウザ言語で案内文を出し、言語メニューは各言語のトップページへ飛びます。

## 開発者向け：新しい言語を追加するには？

イタリア語（Italiano、コード `it`）を追加する場合を例にします。

1. **ルートとディレクトリを登録**：`astro.config.mjs` の `locales` に `it: { label: 'Italiano', lang: 'it' }`、`LOCALE_DIRS` に `it` を追加します。内部リンク、画像、リダイレクト、言語メタデータ処理が新しいディレクトリを認識できるようにします。
2. **サイドバー、注意書き、脚注を翻訳**：同じファイルの `SIDEBAR_I18N` を揃え、`LOCALE_TRANSLATION_FILES` に `it: 'it.json'` を登録し、`FOOTNOTE_LABELS` と `FOOTNOTE_BACK_LABELS` にイタリア語を追加します。
3. **UI 文字列を翻訳**：`src/utils/i18n.ts` の `SUPPORTED_LANGUAGES` にコード、名称、略称、ディレクトリを登録し、検索、Pagefind、404 を含む `UI_TRANSLATIONS` の全キーを翻訳します。
4. **全コンテンツを翻訳**：`src/content/docs/it/index.mdx` と、デフォルト言語に一対一で対応する `src/content/docs/it/canvas/` の全訳文を作成します。Frontmatter のキー、見出し階層、コードフェンスの構造を揃えます。中国語を仮置きしただけでは翻訳完了になりません。
5. **翻訳画像を用意**：同名の画像を `public/images/canvas/it/` に置きます。本当に共用する画像だけを `scripts/check-localized-images.mjs` の `SHARED_ALLOWLIST` に登録します。図の生成ツールを使う場合は `scripts/diagram-i18n/it.mjs` を追加し、`scripts/generate-diagram-locales.mjs` の `LOCALES` に登録します。スクリーンショットツールを使う場合は `scripts/capture-ui-shots.mjs` の `LOCALES` と `SEARCH_WORDS` も更新します。
6. **検証対象を追加**：`scripts/audit-i18n.mjs` の `locales` と `LATIN`、`scripts/check-anchors.mjs` の `LOCALES`、`scripts/check-localized-images.mjs` の `LOCALE_DIRS` に `it` を追加します。`scripts/check-links.mjs` の言語コードとディレクトリの対応表 `LANG_DIRS` に `['it', 'it']` を追加します。`scripts/check-images.mjs` は全画像ディレクトリを再帰走査するため言語登録は不要です。
7. **先にソースと画像を検証**：リポジトリルートで `node scripts/audit-i18n.mjs` と `node scripts/check-images.mjs` を実行します。後者は PNG ヘッダーと最小サイズのみを検証するため、画像内の翻訳やレイアウトは目視確認が必要です。
8. **公開前に完全検証**：`pnpm run verify` でビルドと翻訳画像参照、リンク、アンカー、言語メタデータの検証を行います。`pnpm run preview` で新言語のトップページ、本文、言語切り替え、サイト全体検索を確認します。検証を削除せず、すべての失敗を修正してから公開します。

## 開発者向け：UI 文字列を追加・変更するには？

新しい UI 要素を追加するときは、`src/utils/i18n.ts` の `UI_TRANSLATIONS` に文字列を追加します。

```typescript
// ファイルパス: src/utils/i18n.ts
// 辞書は「言語 → キー」の 2 階層で構成され、getTranslation の読み取り順序と一致しています
export const UI_TRANSLATIONS: Record<string, Record<string, string>> = {
  // ステップ 1: デフォルト言語 zh-CN に文字列を追加する（欠けている場合は UI にキー名が fallback 表示される）
  'zh-CN': {
    'nav.plugins': '插件生态',
    // ...その他の既存の文字列
  },
  // ステップ 2: 他の言語に同じキー名の翻訳を追加する。未追加の言語は自動的に簡体字中国語へ fallback する
  en: {
    'nav.plugins': 'Plugins',
  },
  ja: {
    'nav.plugins': 'プラグイン',
  },
};
```

次に、コンポーネント内で `getTranslation` を呼び出し、現在の言語を渡します。

```astro
---
import { getLangFromLocale, getTranslation, localizedHref } from '../../utils/i18n';
const lang = getLangFromLocale(Astro.currentLocale);
---

<a href={localizedHref('/plugins/', lang)}>{getTranslation('nav.plugins', lang)}</a>
```

文字列はビルド時に対応言語の静的なテキストとしてレンダリングされ、実行時のオーバーヘッドはありません。

この例は 3 言語の抜粋です。新しいキーは登録済みの全言語で翻訳してください。中国語へのフォールバックは保護機能であり、翻訳完了ではありません。
