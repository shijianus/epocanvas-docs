**EpoCanvas Docs** の使用・執筆・デプロイ中に問題が起きたら、ここで該当する項目を探してください。「ローカル起動 → ドキュメント執筆 → 検索 → デプロイ」の順に、よくある原因と確認手順を示しています。実際のエラーと確認結果に基づいて判断してください。このページは、現在の候補版ですべての解決方法を実測して成功した記録ではありません。

---

## 1. ローカルの起動とインストールの問題

### Q1: `pnpm run dev` を実行するとポート 4321 が使用中と表示される

- **原因**: 以前に起動した開発サーバーが完全に終了していないか、別のプログラムがポート 4321 を占有しています。
- **解決方法**: 別のポートで起動します:

  ```bash
  pnpm run dev --port 4322
  ```

### Q2: 依存関係のインストール時にエラーが出る
- **原因**: このサイトは passthrough 画像サービスを使っており、実行時に画像を最適化しません。まずターミナルの具体的なエラーを確認してください。Node.js または pnpm のバージョンが基準外であることがよくあります。
- **解決方法**: Node.js 22.x ≥ 22.23.4 / 24.x ≥ 24.12.0 と pnpm 10.34.5 を使い、`pnpm-lock.yaml` を残したまま再現可能なインストールを実行します:
  ```bash
  pnpm install --frozen-lockfile
  ```

### Q3: `pnpm install` を実行すると `packages field missing or empty` エラーになる

- **原因**: `pnpm-workspace.yaml` の内容が空か、形式が不完全です。pnpm はこれをワークスペース設定ファイルとして解析し、エラーを出します。
- **解決方法**: ファイルに `packages` フィールドが含まれていることを確認します:

  ```yaml
  packages:
    - .
  ```

## 2. ドキュメント執筆とレンダリングの問題

### Q4: 新しい Markdown を作成したのに、左側のサイドバーに表示されない

- **原因**: サイドバーのカタログは手動で宣言する仕組みで、新規ファイルは設定への登録が必要です。
- **解決方法**: `astro.config.mjs` を開き、`sidebar` 配列の適切なグループに追加します:

  ```javascript
  { label: '新機能の説明', link: '/canvas/new-feature/' }
  ```

### Q5: ターミナルに `"title" is required` エラーが出る

- **原因**: Markdown の先頭で `title` を書き忘れたか、先頭の 3 つのハイフン `---` の形式が不正です。
- **解決方法**: ファイル最上部の Frontmatter を確認します:

  ```yaml
  ---
  title: 記事タイトル
  description: 記事の説明
  ---
  ```

### Q6: 同じ内容の大きな見出しが 2 つ表示される

- **原因**: 本文にもう 1 つレベル 1 の見出し `#` を書いています。Frontmatter の `title` はすでに大見出しとしてレンダリングされるため、本文で `#` を書くと必ず重複します。
- **解決方法**: 本文から `#` 見出しを削除し、節は `##` から始めます。完全なルールは[レンダリングルールの詳細](/canvas/rendering/#見出しのルール)を参照してください。

### Q7: `> [!TIP]` と書いたのに吹き出しが色づかず、文字がそのまま表示される

- **原因**: GitHub 風の `> [!TIP]` 引用ブロック構文はサポートされておらず、Markdown コンパイラが認識しません。
- **解決方法**: 3 コロン構文に書き換えます:

  ```markdown
  :::tip
  こちらが正しい書き方です。
  :::
  ```

### Q8: 挿入した画像が割れたアイコンで表示される

- **原因**: 画像のパスが間違っているか、画像が `public/` 静的ディレクトリに置かれていません。
- **解決方法**:
  1. 画像が `public/images/canvas/ui-docs-reading.png` に保存されていることを確認します。
  2. 参照するときは `/` で始まる絶対パスを使います: `![説明](/images/canvas/ui-docs-reading.png)`。`../public/...` のような相対パスは書かないでください。

## 3. 検索機能の問題

### Q9: ローカルの `pnpm dev` でデバッグしているとき、サイト全体検索で新しく書いた記事が見つからない

- **原因**: サイト全体検索はビルド時に生成される Pagefind のインデックスに依存しています。開発モードでは `Ctrl+K` ダイアログがインデックスを読み込まず（開いても検索入力欄がない）、サイト全体検索は使用できません。これはフレームワークの想定動作であり、サイトの故障ではありません。
- **解決方法**: 完全にビルドしてからプレビューサーバーで検証します:

  ```bash
  pnpm run build
  pnpm run preview
  ```

  トップバーのページ内検索はこの制限を受けないため、開発中はそれを使って現在のページの内容を直接探せます。

### Q10: `Ctrl+K` を押しても検索ポップアップが開かない

- **原因**: 一部の IME（入力メソッド）、クリップボードツール、スクリーンショットソフトが `Ctrl+K` / `Cmd+K` のショートカットキーを占有しています。
- **解決方法**: 検索ボックスの右側にある `Ctrl K` の小さなバッジをクリックしても、サイト全体検索のポップアップを開けます。

## 4. Cloudflare Pages のデプロイの問題

### Q11: バインドしたばかりのカスタムドメインで SSL ハンドシェイク失敗 (Error 525) と表示される

- **原因**: Error 525 だけで証明書の発行待ちと判断することはできません。ドメイン検証、証明書の状態、DNS レコード、プロキシ設定、エラーの詳細を確認します。
- **解決方法**: **Custom domains** でドメイン検証と証明書の状態を確認し、DNS とプロキシ設定を調べ、デフォルトの `pages.dev` ドメインと比較してください。決まった時間待つだけでは解決を確認できません。両ドメインが使えるかは実際のリクエストで判断します。[デプロイの問題の切り分け](/canvas/cloudflare/)を参照してください。

### Q12: `pnpm run deploy` を実行すると `Project not found` エラーになる

- **原因**: デプロイコマンドの `--project-name` パラメータが、Cloudflare コンソールのプロジェクト名と一致していません。または、このマシンでログインしていない可能性もあります。
- **解決方法**:
  1. まず `npx wrangler whoami` を実行してログイン済みか確認します。
  2. Cloudflare コンソールでプロジェクト名を確認し、必要に応じて `scripts/verify-release.mjs` の `--project-name` パラメータを修正します。

最初に `npx wrangler login` で認証し、`pnpm run deploy` を実行します。デプロイを担当する `scripts/verify-release.mjs` は、`main` 以外のブランチ、変更の残る作業ツリー、リモートの実際の `origin/main` コミットと一致しない HEAD を拒否します。`pnpm run verify` が通ってから Wrangler を呼び出します。プロジェクト名の定義先はこのスクリプトであり、`package.json` ではありません。

## 5. コミット前のローカルセルフチェック

GitHub へプッシュする前に、共通の自己チェックを実行してください。テスト、設定チェック、Astro 型チェック、ビルド、コンテンツと成果物の検査を含みます。

```bash
pnpm run verify
```

`pnpm run verify` の全段階が通過し、終了コードが 0 であることを確認してください。`0 errors` や `Complete!` だけでは全検査の終了を示しません。CI（`build.yml`）も同じ検証を実行しますが、表示結果は手動で確認する必要があります。
