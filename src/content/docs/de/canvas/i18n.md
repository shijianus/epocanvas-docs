**EpoCanvas Docs** verfügt über eine vollständige Mehrsprachigkeit auf Inhaltsebene: Sowohl die Oberflächentexte wie Navigation, Seitenleiste und Suchhinweise als auch der Haupttext jedes einzelnen Dokuments liegen in 10 unabhängigen Sprachversionen vor. Wenn Sie oben rechts auf der Seite eine Sprache auswählen, gelangen Sie zur Version desselben Artikels in der Zielsprache – Haupttext und Oberfläche wechseln gemeinsam.

---

## Liste der unterstützten Sprachen

Die Website bietet derzeit 10 Sprachen, wobei Chinesisch (vereinfacht) die Standardsprache ist:

| Sprache | Sprachname | URL-Präfix | Kürzel in der Oberfläche |
| :--- | :--- | :--- | :--- |
| 简体中文 | **Vereinfachtes Chinesisch** (Standard) | kein Präfix | ZH |
| 繁體中文 | Traditionelles Chinesisch | `/zh-tw/` | TW |
| English | Englisch | `/en/` | EN |
| 日本語 | Japanisch | `/ja/` | JA |
| 한국어 | Koreanisch | `/ko/` | KO |
| Español | Spanisch | `/es/` | ES |
| Français | Französisch | `/fr/` | FR |
| Deutsch | Deutsch | `/de/` | DE |
| Русский | Russisch | `/ru/` | RU |
| Português | Portugiesisch | `/pt/` | PT |

Die Sprachliste steht in `SUPPORTED_LANGUAGES` in `src/utils/i18n.ts`. In `astro.config.mjs` registriert `locales` die Routen; `LOCALE_DIRS` erkennt die Verzeichnisse der anderen Sprachen. Beim Hinzufügen einer Sprache müssen auch Wörterbücher und Prüfscripte angepasst werden.

## Sprache wechseln

1. Suchen Sie rechts in der Navigationsleiste oben auf der Seite den Sprach-Button (er zeigt das Kürzel der aktuellen Sprache, z. B. `ZH`);
2. klicken Sie auf den Button; das Dropdown-Menü listet alle 10 Sprachen auf;
3. klicken Sie auf die Zielsprache (z. B. `English` oder `日本語`);
4. der Browser wechselt zur Version des aktuellen Artikels in der Zielsprache; Navigation, Seitenleiste, Inhaltsverzeichnis und Haupttext wechseln gemeinsam in die Zielsprache.

## URL-Regeln

Die Seiten jeder Sprache haben ein eigenes URL-Präfix; derselbe Artikel unterscheidet sich zwischen den Sprachen nur durch das Präfix:

```text
/canvas/i18n/          → Chinesisch, vereinfacht (Standardsprache, ohne Präfix)
/en/canvas/i18n/       → Englisch
/ja/canvas/i18n/       → Japanisch
/zh-tw/canvas/i18n/    → Chinesisch, traditionell
```

- Die Sprachinformation ist direkt in der URL kodiert; die Seite nach dem Sprachwechsel lässt sich direkt als Lesezeichen speichern und teilen, und Suchmaschinen können sie sprachweise getrennt aufnehmen;
- interne Links innerhalb der Seite (Navigation, Seitenleiste, Empfehlungslinks im Haupttext) erhalten automatisch das Präfix der aktuellen Sprache; wer innerhalb einer Sprache weiterliest, wird also nicht auf chinesische Seiten zurückgeworfen;
- jede Sprachversion ist eine beim Build erzeugte, eigenständige statische Seite; das `<html lang>`-Attribut der Seite entspricht der Sprache, sodass Screenreader und Übersetzungswerkzeuge sie korrekt erkennen.

## Was passiert bei fehlenden Übersetzungen?

Fehlt eine Übersetzung, kann Starlight die Route der Zielsprache mit dem vereinfachten chinesischen Haupttext erzeugen. Das ist ein technischer Fallback, keine erlaubte Veröffentlichungspraxis: Die Seite kann die Zielsprache deklarieren, obwohl ihr Text chinesisch ist.

Dieses Projekt verlangt die Startseite und alle Artikel in sämtlichen 10 Sprachen. `node scripts/audit-i18n.mjs` prüft fehlende oder zusätzliche Seiten, Frontmatter, Überschriften und Codeblock-Struktur. Fehlende Übersetzungen führen zu einem Exitcode ungleich null und blockieren `pnpm run verify` und CI. Ergänzungen und Änderungen müssen vor der Veröffentlichung in allen Sprachen vorliegen; erst Chinesisch zu veröffentlichen und später zu übersetzen ist nicht zulässig. Ein erfolgreicher `pnpm run build` allein bedeutet nicht, dass die Veröffentlichungsprüfungen bestanden sind.

## Wie die Mehrsprachigkeit technisch funktioniert

Die Mehrsprachigkeit stützt sich auf die Internationalisierungsmechanismen von Astro und Starlight. Der Build-Ablauf:

1. **Inhaltsordner nach Sprachen getrennt**: Die Dokumente der Standardsprache liegen unter `src/content/docs/` (Chinesisch, vereinfacht), die anderen Sprachen unter `src/content/docs/<Sprache>/`; die Verzeichnisstruktur entspricht exakt der chinesischen, die englische Version von „Mehrsprachigkeit & Sprachwechsel“ liegt z. B. unter `src/content/docs/en/canvas/i18n.md`;
2. **alle Sprachseiten beim Build erzeugt**: `astro build` liest die `locales`-Konfiguration aus `astro.config.mjs` und erzeugt für jede Sprache einen vollständigen Satz statischer Seiten;
3. **Oberflächentexte sprachweise gerendert**: Oberflächentexte wie Kopfnavigation, Suchhinweise und Verzeichnistitel geben die Komponenten über `getTranslation(key, lang)` direkt beim Build in der jeweiligen Sprache aus; es gibt kein Skript, das zur Laufzeit Texte austauscht;
4. **interne Links im Haupttext automatisch lokalisiert**: Das Plugin `rehypeLocalizeInternalLinks` in der Build-Pipeline versieht interne Links wie `/canvas/xxx` im übersetzten Haupttext automatisch mit dem Präfix der aktuellen Sprache;
5. **Volltextsuche sprachweise getrennt**: Pagefind erstellt für jede Sprache einen eigenen Index; auf einer englischen Seite liefert die Suche nur englische Ergebnisse.
6. **Lokalisierte Bilder und Prüfungen**: `rehypeLocalizeDiagramImages` ersetzt `/images/canvas/<Datei>` durch `/images/canvas/<Sprache>/<Datei>`, wenn eine gleichnamige lokalisierte Datei vorhanden ist; andernfalls bleibt das Original. Die Veröffentlichungsprüfung `check-localized-images.mjs` verlangt jedoch lokalisierte Bilder. Nur tatsächlich gemeinsam genutzte Bilder, etwa in `SHARED_ALLOWLIST` eingetragene Screenshots fremder Dienste, sind ausgenommen. Der Fallback ersetzt keine Übersetzung;
7. **Hinweisboxen und Fußnoten folgen der Seitensprache**: `rehypeLocalizeAsides` und `rehypeLocalizeFootnotes` setzen die Titel der Hinweisboxen und die Fußnotentexte anhand des Sprachverzeichnisses der Quelldatei – Starlight erschließt die Sprache in remark über den absoluten Pfad, der lokale Build übergibt aber einen relativen Pfad, ohne diesen Schritt fiele alles auf Chinesisch zurück;
8. **hreflang und 404-Seite**: nach dem Build ergänzt `hreflangXDefault()` je Seite einen `hreflang="x-default"`-Eintrag auf die vereinfacht-chinesische Fassung, und `src/pages/404.astro` nutzt dasselbe Wörterbuch für die Meldung in der Browsersprache; das Sprachmenü dort verweist auf die Startseite der jeweiligen Sprache.

## Für Entwickler: Wie fügt man eine Sprache hinzu?

Am Beispiel des Hinzufügens von Italienisch (Italiano, Code `it`):

1. **Route und Verzeichnis registrieren**: Ergänzen Sie `it: { label: 'Italiano', lang: 'it' }` in `locales` und `it` in `LOCALE_DIRS` in `astro.config.mjs`, damit Links, Bilder, Weiterleitungen und Sprachmetadaten das neue Verzeichnis erkennen.
2. **Seitenleiste, Hinweise und Fußnoten übersetzen**: Vervollständigen Sie `SIDEBAR_I18N` in derselben Datei; ergänzen Sie `it: 'it.json'` in `LOCALE_TRANSLATION_FILES` sowie italienische Einträge in `FOOTNOTE_LABELS` und `FOOTNOTE_BACK_LABELS`.
3. **Oberfläche übersetzen**: Registrieren Sie Code, Name, Kürzel und Verzeichnis in `SUPPORTED_LANGUAGES` in `src/utils/i18n.ts` und übersetzen Sie alle Schlüssel in `UI_TRANSLATIONS`, einschließlich Suche, Pagefind und 404-Meldungen.
4. **Alle Inhalte übersetzen**: Erstellen Sie `src/content/docs/it/index.mdx` und vollständige Übersetzungen unter `src/content/docs/it/canvas/`, die den Dateien der Standardsprache eins zu eins entsprechen. Frontmatter-Schlüssel, Überschriftenebenen und Codeblock-Struktur müssen übereinstimmen. Kopierter chinesischer Platzhaltertext gilt nicht als Übersetzung.
5. **Lokalisierte Bilder vorbereiten**: Legen Sie gleichnamige Dateien unter `public/images/canvas/it/` ab. Nur tatsächlich gemeinsame Bilder gehören in `SHARED_ALLOWLIST` in `scripts/check-localized-images.mjs`. Für den Diagrammgenerator ergänzen Sie `scripts/diagram-i18n/it.mjs` und einen Eintrag in `LOCALES` in `scripts/generate-diagram-locales.mjs`; für das Screenshot-Werkzeug aktualisieren Sie `LOCALES` und `SEARCH_WORDS` in `scripts/capture-ui-shots.mjs`.
6. **Prüfbereiche erweitern**: Ergänzen Sie `it` in `locales` und `LATIN` in `scripts/audit-i18n.mjs`, in `LOCALES` in `scripts/check-anchors.mjs` sowie in `LOCALE_DIRS` in `scripts/check-localized-images.mjs`. Fügen Sie `['it', 'it']` zur Sprachcode-Verzeichnis-Zuordnung `LANG_DIRS` in `scripts/check-links.mjs` hinzu. `scripts/check-images.mjs` durchsucht alle Bildverzeichnisse rekursiv und benötigt keine Sprachregistrierung.
7. **Quellen und Bilder zuerst prüfen**: Führen Sie `node scripts/audit-i18n.mjs` und `node scripts/check-images.mjs` im Repository-Stamm aus. Letzteres prüft nur PNG-Signatur und Mindestgröße, nicht Bildübersetzung oder Layout.
8. **Vor der Veröffentlichung vollständig prüfen**: `pnpm run verify` baut die Website und prüft lokalisierte Bildreferenzen, Links, Anker und Sprachmetadaten. Prüfen Sie mit `pnpm run preview` Startseite, Artikel, Sprachwechsel und Volltextsuche der neuen Sprache. Beheben Sie alle Fehler, statt Prüfungen zum Veröffentlichen zu entfernen.

## Für Entwickler: Wie fügt man Oberflächentexte hinzu oder ändert sie?

Fügen Sie bei neuen Oberflächenelementen die Texte in `UI_TRANSLATIONS` in `src/utils/i18n.ts` hinzu:

```typescript
// Dateipfad: src/utils/i18n.ts
// Das Wörterbuch ist zweistufig nach „Sprache → Textschlüssel“ organisiert,
// entsprechend der Lesereihenfolge von getTranslation
export const UI_TRANSLATIONS: Record<string, Record<string, string>> = {
  // Schritt 1: Texte in der Standardsprache zh-CN hinzufügen
  // (fehlt ein Text, zeigt die Oberfläche als Fallback den Schlüsselnamen an)
  'zh-CN': {
    'nav.plugins': '插件生态',
    // ...übrige bereits vorhandene Texte
  },
  // Schritt 2: für andere Sprachen dieselben Schlüssel nachpflegen;
  // Sprachen ohne Eintrag fallen automatisch auf Chinesisch zurück
  en: {
    'nav.plugins': 'Plugins',
  },
  ja: {
    'nav.plugins': 'プラグイン',
  },
};
```

Rufen Sie anschließend in der Komponente `getTranslation` auf und übergeben Sie die aktuelle Sprache:

```astro
---
import { getLangFromLocale, getTranslation, localizedHref } from '../../utils/i18n';
const lang = getLangFromLocale(Astro.currentLocale);
---

<a href={localizedHref('/plugins/', lang)}>{getTranslation('nav.plugins', lang)}</a>
```

Die Texte werden beim Build als statischer Text in der jeweiligen Sprache gerendert; es entsteht kein Laufzeit-Overhead.

Das Beispiel zeigt nur drei Sprachzweige. Neue Texte müssen dennoch in jeder registrierten Sprache vorliegen; chinesischer Fallback ist eine Schutzfunktion, keine fertige Übersetzung.
