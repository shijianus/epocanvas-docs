**EpoCanvas Docs**를 사용하거나 작성·배포하는 중 문제가 생기면 여기서 해당 항목을 찾아보세요. "로컬 실행 → 문서 작성 → 검색 → 배포" 순서로 흔한 원인과 점검 절차를 제시합니다. 실제 오류와 점검 결과를 바탕으로 판단하세요. 이 페이지는 현재 후보 버전에서 모든 해결 방법을 실측하여 통과했다는 기록이 아닙니다.

---

## 1. 로컬 실행 및 설치 문제

### Q1: `pnpm run dev` 실행 시 포트 4321가 이미 사용 중이라고 표시됨

- **원인**: 이전에 실행한 개발 서버가 완전히 종료되지 않았거나, 다른 프로그램이 4321 포트를 사용 중입니다.
- **해결 방법**: 다른 포트로 실행합니다:

  ```bash
  pnpm run dev --port 4322
  ```

### Q2: 의존성 설치 중 오류가 표시됨
- **원인**: 이 사이트는 passthrough 이미지 서비스를 사용하며 런타임에 이미지를 최적화하지 않습니다. 먼저 터미널의 구체적인 오류를 확인하세요. Node.js 또는 pnpm 버전이 프로젝트 기준과 맞지 않는 경우가 흔합니다.
- **해결 방법**: Node.js 22.x ≥ 22.23.4 / 24.x ≥ 24.12.0 및 pnpm 10.34.5를 사용하고 `pnpm-lock.yaml`을 유지한 채 재현 가능한 설치를 실행합니다.
  ```bash
  pnpm install --frozen-lockfile
  ```

### Q3: `pnpm install` 실행 시 `packages field missing or empty` 오류가 발생함

- **원인**: `pnpm-workspace.yaml` 내용이 비어 있거나 형식이 불완전하여, pnpm이 이를 워크스페이스 설정 파일로 해석하며 오류를 냅니다.
- **해결 방법**: 파일에 `packages` 필드가 포함되어 있는지 확인합니다:

  ```yaml
  packages:
    - .
  ```

## 2. 문서 작성 및 렌더링 문제

### Q4: 새 Markdown 파일을 만들었는데 왼쪽 사이드바에 보이지 않음

- **원인**: 사이드바 목차는 수동으로 선언하는 방식이라 새 파일은 반드시 설정에 등록해야 합니다.
- **해결 방법**: `astro.config.mjs`를 열어 `sidebar` 배열의 적절한 그룹 아래에 추가합니다:

  ```javascript
  { label: '새 기능 설명', link: '/canvas/new-feature/' }
  ```

### Q5: 터미널에 `"title" is required` 오류가 표시됨

- **원인**: Markdown 머리 부분에서 `title`을 누락했거나, 맨 앞의 세 개 가로줄 `---` 형식이 올바르지 않습니다.
- **해결 방법**: 파일 맨 위의 Frontmatter를 확인합니다:

  ```yaml
  ---
  title: 문서 제목
  description: 문서 설명
  ---
  ```

### Q6: 페이지에 똑같은 대제목이 두 개 나타남

- **원인**: 본문에 수준 1 제목 `#`을 또 썼습니다. Frontmatter의 `title`이 이미 대제목으로 렌더링되므로 본문에 `#`을 쓰면 반드시 중복됩니다.
- **해결 방법**: 본문의 `#` 제목을 삭제하고 소제목은 `##`부터 시작합니다. 전체 규칙은 [렌더링 규칙 상세](/canvas/rendering/#제목-규칙)를 참조하세요.

### Q7: `> [!TIP]`을 썼는데 콜아웃이 색이 변하지 않고 글자가 그대로 표시됨

- **원인**: GitHub 스타일의 `> [!TIP]` 인용 블록 문법은 지원되지 않으며, Markdown 컴파일러가 인식하지 못합니다.
- **해결 방법**: 세 개의 콜론 문법으로 바꿉니다:

  ```markdown
  :::tip
  올바른 작성 방법입니다.
  :::
  ```

### Q8: 삽입한 이미지가 깨진 그림으로 표시됨

- **원인**: 이미지 경로가 잘못되었거나, 이미지를 `public/` 정적 디렉터리에 넣지 않았습니다.
- **해결 방법**:
  1. 이미지가 `public/images/canvas/ui-docs-reading.png`에 저장되어 있는지 확인합니다;
  2. 참조할 때는 `/`로 시작하는 절대 경로를 사용합니다: `![설명](/images/canvas/ui-docs-reading.png)`, `../public/...` 같은 상대 경로는 쓰지 않습니다.

## 3. 검색 기능 문제

### Q9: 로컬에서 `pnpm dev`로 디버깅할 때 전역 검색으로 방금 쓴 새 글이 검색되지 않음

- **원인**: 사이트 전체 검색은 빌드 시 생성되는 Pagefind 인덱스에 의존합니다. 개발 모드에서는 `Ctrl+K` 대화상자가 인덱스를 불러오지 않아(열어도 검색 입력창이 없음) 전역 검색을 사용할 수 없습니다. 프레임워크의 의도된 동작이며 사이트 결함이 아닙니다.
- **해결 방법**: 완전히 빌드한 후 미리보기 서버로 검증합니다:

  ```bash
  pnpm run build
  pnpm run preview
  ```

  상단 바의 페이지 내 찾기는 이 제한을 받지 않으므로, 개발할 때 현재 페이지 내용을 찾는 데 바로 사용할 수 있습니다.

### Q10: `Ctrl+K`를 눌러도 검색 팝업이 열리지 않음

- **원인**: 일부 입력기, 클립보드 도구 또는 스크린샷 소프트웨어가 `Ctrl+K` / `Cmd+K` 단축키를 사용 중입니다.
- **해결 방법**: 검색창 오른쪽의 `Ctrl K` 작은 배지를 직접 클릭해도 사이트 전체 검색 팝업을 열 수 있습니다.

## 4. Cloudflare Pages 배포 문제

### Q11: 방금 연결한 커스텀 도메인에서 SSL 핸드셰이크 실패(Error 525)가 표시됨

- **원인**: Error 525만으로 인증서 발급 대기 중이라고 판단할 수 없습니다. 도메인 검증, 인증서 상태, DNS 레코드, 프록시 설정과 오류 세부 정보를 확인해야 합니다.
- **해결 방법**: **Custom domains**에서 도메인 검증과 인증서 상태를 확인한 뒤 DNS 및 프록시 설정을 점검하고 기본 `pages.dev` 도메인과 비교하세요. 정해진 시간만 기다리지 말고 두 도메인 모두 실제 요청 결과로 확인해야 합니다. [배포 문제 해결](/canvas/cloudflare/)을 참고하세요.

### Q12: `pnpm run deploy` 실행 시 `Project not found` 오류가 발생함

- **원인**: 배포 명령어의 `--project-name` 매개변수가 Cloudflare 콘솔의 프로젝트 이름과 일치하지 않거나, 이 컴퓨터에서 로그인하지 않았을 수 있습니다.
- **해결 방법**:
  1. 먼저 `npx wrangler whoami`로 로그인 여부를 확인합니다;
  2. Cloudflare 콘솔에서 프로젝트 이름을 확인하고, 필요하면 `scripts/verify-release.mjs`에서 `--project-name` 매개변수를 수정합니다.

먼저 `npx wrangler login`으로 인증한 뒤 `pnpm run deploy`를 실행합니다. 배포를 담당하는 `scripts/verify-release.mjs`는 `main`이 아닌 브랜치, 변경 사항이 남아 있는 작업 트리, 원격 `origin/main`의 실제 커밋과 일치하지 않는 HEAD를 거부합니다. `pnpm run verify`가 통과한 뒤 Wrangler를 호출합니다. 프로젝트 이름은 `package.json`이 아니라 이 스크립트에 정의되어 있습니다.

## 5. 제출 전 로컬 자가 점검

GitHub에 푸시하기 전에 공통 자가 점검 명령을 실행하세요. 테스트, 설정 검사, Astro 타입 검사, 빌드 및 콘텐츠/결과물 검사를 포함합니다.

```bash
pnpm run verify
```

`pnpm run verify`의 모든 단계가 통과하고 종료 코드가 0인지 확인해야 합니다. `0 errors` 또는 `Complete!`만으로는 전체 검사가 끝났다고 볼 수 없습니다. CI(`build.yml`)도 같은 검증을 실행하며 화면은 여전히 직접 확인해야 합니다.
