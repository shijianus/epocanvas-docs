**EpoCanvas Docs**는 페이지 내 찾기와 사이트 전체 검색을 제공합니다. 화면 너비가 `64rem` 이상이면 상단 입력창이 표시되며, `64rem` 미만이면 전체 검색 버튼만 표시됩니다. 전체 검색은 Pagefind 정적 인덱스를 사용하며 검색 백엔드가 필요 없습니다.

---

## 두 가지 검색을 각각 언제 사용하나요?

| 상황 | 사용할 검색 | 조작 방법 |
| :--- | :--- | :--- |
| 내용이 **현재 글**에 있음 | 페이지 내 찾기 | `64rem` 이상에서 상단 입력창 사용. 좁은 화면은 브라우저의 페이지에서 찾기 사용 |
| **어느 글**인지 모름 | 사이트 전체 검색 | 상단 검색 버튼 클릭 또는 `Ctrl + K`(Mac은 `Cmd + K`) |

---

## 페이지 내 찾기: 상단 바 검색창

다음 조작은 화면 너비가 `64rem` 이상일 때 적용됩니다. 상단 입력창에 키워드를 입력하세요. 더 좁은 화면에서는 입력창, 개수와 이동 버튼이 숨겨지고 전체 검색을 여는 돋보기 버튼만 남습니다. 현재 글을 찾으려면 브라우저의 페이지에서 찾기를 사용하세요.

![상단 바 페이지 내 찾기 주석 다이어그램: ① 입력창 ② 매칭 카운트 ③ 위아래 이동 ④ 지우기 ⑤ 페이지 하이라이트](/images/canvas/ui-inpage-search.png)

*그림: 기존 페이지 내 찾기 참고 화면입니다. 현재 개수, 이전/다음 및 지우기 버튼은 입력창 안이 아니라 아래에 표시되며 좁은 화면에서는 숨겨집니다. 위치, 개수나 배치가 다르면 실제 인터페이스를 기준으로 하세요.*

### 키워드 입력

단어나 `pnpm`, `astro.config.mjs` 같은 코드를 입력할 수 있습니다. 본문의 보이는 일치 텍스트를 강조하고 첫 위치로 이동합니다. 내비게이션과 숨겨진 내용은 제외됩니다.

### 매칭 결과 사이를 이동

- 입력창에 포커스가 있을 때 <kbd>Enter</kbd> 또는 아래 화살표 버튼: 다음 일치 항목으로 이동;
- 입력창에 포커스가 있을 때 <kbd>Shift + Enter</kbd> 또는 위 화살표 버튼: 이전 일치 항목으로 이동;
- 입력창 아래에 현재 번호와 총수를 `N/M`(예: `3/9`)으로 표시합니다.

### 검색 지우고 페이지 복원

입력창에서 <kbd>Esc</kbd>를 누르거나 `×` 지우기 버튼을 클릭하면 검색어와 강조 표시가 지워집니다.

## 사이트 전체 검색: Ctrl+K 팝업

<kbd>Ctrl</kbd> + <kbd>K</kbd>(Mac은 <kbd>Cmd</kbd> + <kbd>K</kbd>) 또는 상단 전체 검색 버튼으로 팝업을 엽니다. 넓은 화면은 단축키 배지, `64rem` 미만은 돋보기 아이콘입니다. 둘 다 전체 검색을 열며 페이지 내 입력이 아닙니다.

![사이트 전체 검색 팝업 주석 다이어그램: ① 트리거 배지 ② 검색 입력창 ③ 결과 목록 ④ 단축키 바](/images/canvas/ui-search-modal.png)

*그림: 입력창과 결과 목록을 보여 주는 기존 참고 화면입니다. 버튼 위치나 단축키 안내가 다르면 실제 화면과 아래 설명을 따르세요. 현재는 Tab으로 링크에 포커스를 옮깁니다. 좁은 화면에서는 하단 안내가 숨겨질 수 있습니다.*

### 키워드 입력

현재 페이지 언어의 단어나 `pnpm`, `astro.config.mjs` 같은 코드를 입력하세요. Pagefind는 관련성으로 정렬하며 제목 일치가 항상 첫 번째라는 보장은 없습니다.

### 결과 목록 둘러보기

결과는 문서별 제목, 일치하는 발췌문, 사용 가능한 섹션 하위 결과로 구성됩니다. 제목과 하위 결과는 링크입니다. 제목은 문서를 열고 섹션 링크는 앵커로 이동합니다. 제목은 펼치기/접기 버튼이 아닙니다.

### 키보드로 전 과정 완료하기

- <kbd>Tab</kbd> / <kbd>Shift + Tab</kbd>: 입력창, 버튼, 결과 링크 사이에서 포커스를 순서대로 이동;
- 결과 링크에 포커스가 있을 때 <kbd>Enter</kbd>: 해당 링크를 엽니다. 섹션 링크는 앵커로 이동;
- <kbd>Esc</kbd>: 팝업을 닫습니다.

현재 Pagefind UI는 <kbd>↑</kbd> / <kbd>↓</kbd>로 결과를 선택하거나 문서 제목을 클릭해 일치 단락을 펼치는 기능을 지원하지 않습니다.

## 검색은 왜 이렇게 빠를까요?

![EpoCanvas Docs 이중 모드 검색 메커니즘 비교 다이어그램: 왼쪽 상단 바 페이지 내 찾기(DOM 순회 하이라이트, 실시간 카운트, 부드러운 스크롤), 오른쪽 사이트 전체 검색 팝업(Ctrl+K로 호출, Pagefind WASM 메모리 역인덱스 초 단위 매칭)](/images/canvas/docs-search-flow.svg)

*그림: 이중 모드 검색의 작동 메커니즘 비교. 왼쪽은 상단 바의 페이지 내 키워드 빠른 위치 찾기, 오른쪽은 Pagefind WASM 기반 사이트 전체 정적 인덱스 검색이며, 둘 모두 완전히 브라우저에서 로컬로 실행됩니다.*

많은 웹사이트의 문서 검색은 요청을 원격 서버의 데이터베이스 질의로 보내야 하므로, 네트워크가 좋지 않으면 하염없이 로딩만 기다려야 합니다.

EpoCanvas Docs는 **Pagefind** 로컬 정적 검색 방식을 사용합니다:

1. **빌드 시점에 인덱스 추출**: `pnpm run build`를 실행하면 시스템이 각 문서의 내용을 자동으로 수집하여 압축된 정적 인덱스 분할 파일 묶음을 생성합니다.
2. **필요한 인덱스 다운로드**: 브라우저가 사이트에서 검색 코드와 필요한 인덱스 조각을 불러옵니다. 최초 로딩이나 캐시가 없을 때는 네트워크 요청이 발생합니다.
3. **브라우저 내 검색**: 인덱스 로딩 후 일치와 정렬은 로컬에서 처리됩니다. 인트라넷에도 검색 리소스를 제공해야 하며 처음부터 네트워크 없이 동작한다는 뜻은 아닙니다.

## 검색 활용 팁

- **단어 분리**: 더 정확한 내용을 찾으려면 여러 단어를 공백으로 구분해 입력하세요(예: `Cloudflare 도메인`).
- **구체적인 단어 사용**: 제목과 섹션 이름으로 범위를 좁힐 수 있지만 순서는 Pagefind의 관련성 정렬에 따릅니다.
- **개발 모드의 제약**: 사이트 전체 인덱스는 빌드 시에만 생성되며, `pnpm run dev`로 시작한 개발 서버에서는 `Ctrl+K` 대화상자가 인덱스를 불러오지 않아 전역 검색을 사용할 수 없습니다. 검색을 확인하려면 `pnpm run build`를 실행한 뒤 `pnpm run preview`로 빌드 결과를 여세요. 페이지 내 찾기는 이 제약을 받지 않습니다.
