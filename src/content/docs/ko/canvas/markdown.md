**EpoCanvas Docs**에서 문서를 추가하거나 편집하는 일은 매우 간단합니다. 모든 본문 내용은 표준 **Markdown** 문법으로 작성하므로, Markdown을 쓸 줄 안다면 바로 문서 작성과 유지 관리에 참여할 수 있습니다.

이 페이지는 사이트 전체 형식 지원의 완전한 목록입니다. 3절에서 기본 Markdown 형식을 항목별로 다루고, 4절에서 이 사이트가 추가로 지원하는 확장 문법을 다룹니다. 각 항목마다 "어떻게 쓰는지"와 "렌더링하면 어떻게 보이는지"를 나란히 보여 주며, 지금 보고 있는 결과가 실제 렌더링 결과입니다.

## 1. 문서 파일은 어디에 두나?

모든 문서 파일은 프로젝트의 `src/content/docs/` 디렉터리에 저장합니다:

```text
src/content/docs/
├── index.mdx          # 사이트의 랜딩 첫 페이지
├── canvas/            # 핵심 문서 장 (간체 중국어, 기본 언어)
│   ├── index.md       # 제품 소개
│   ├── deployment.md  # 빠른 시작
│   ├── layout.md      # 페이지 레이아웃
│   ├── ...            # 기타 문서
└── en/ ja/ ...        # 나머지 9개 언어의 번역, 디렉터리 구조는 중국어판과 완전히 대응
```

- **파일 이름 요구 사항**: 소문자 영어와 하이픈(-)을 사용하고(예: `quickstart-guide.md`), 한글이나 공백을 넣지 마세요. 파일 이름이 접근 경로를 결정합니다: `canvas/deployment.md`는 `/canvas/deployment/`에 해당합니다.
- **확장자**: 보통 일반 텍스트 `.md` 파일이면 충분합니다. 글 안에 인터랙티브 컴포넌트(예: 첫 페이지의 카드 그리드)를 넣어야 한다면 `.mdx` 형식을 사용합니다.
- **사이드바 등록**: 새 파일을 만든 뒤에는 `astro.config.mjs`의 `sidebar` 배열에 등록해야 하며, 그렇지 않으면 왼쪽 목차에 나타나지 않습니다.
- **다국어 번역**: 다른 언어의 번역은 `src/content/docs/<언어>/` 디렉터리에 두며, 하위 디렉터리 구조는 중국어판과 같습니다(예: `en/canvas/deployment.md`는 영어판 빠른 시작에 해당). 아직 번역이 제공되지 않는 페이지는 자동으로 폴백되어 중국어를 표시합니다.

## 2. 머리 메타데이터(Frontmatter)는 어떻게 쓰나?

모든 Markdown 문서의 맨 위에는 하이픈 세 개 `---`로 감싼 YAML 메타데이터 블록이 반드시 포함되어야 합니다:

```yaml
---
title: 빠른 시작 (3분 만에 실행)
description: EpoCanvas Docs 로컬 환경 준비, 의존성 설치와 서버 시작 가이드.
---
```

### 필드 설명

| 필드 이름 | 필수 여부 | 역할 설명 |
| :--- | :--- | :--- |
| `title` | **필수** | 글의 주 제목. 페이지 상단의 큰 제목으로 렌더링되며 브라우저 탭 제목으로도 사용됩니다. |
| `description` | 작성 권장 | 글의 짧은 요약. 브라우저 검색 결과, 소셜 플랫폼 공유 카드의 설명 텍스트로 사용됩니다. |
| `template` | 첫 페이지 전용 | `splash`로 설정하면 사이드바 없는 랜딩 페이지 템플릿을 사용합니다. |

:::tip
문서를 쓸 때 `title`을 누락하면 빌드할 때 Astro가 터미널에 명확한 오류와 파일 이름을 표시하므로, 안내에 따라 보완하면 됩니다.
:::

## 3. 기본 Markdown 형식 전체 보기

이 사이트는 GFM 확장이 포함된 표준 Markdown으로 렌더링하며, 아래 형식을 모두 지원합니다. 먼저 전체 목록을 보고, 항목별로 작성 방법과 렌더링 결과 대조를 확인하세요:

| 형식 | 빠른 작성법 | 용도 |
| :--- | :--- | :--- |
| 제목 | `## 소절 제목` | 장 구조를 정리하고 오른쪽 이 페이지의 목차에 자동 수록 |
| 단락과 줄바꿈 | 빈 줄로 단락 구분 | 본문의 기본 단위 |
| 굵게 / 기울임 / 취소선 | `**굵게**` `*기울임*` `~~취소선~~` | 핵심 문장 강조 |
| 인라인 코드 | `` `명령어` `` | 명령어, 파일 이름, 단축키 표시 |
| 키보드 키 | `<kbd>Ctrl</kbd>` | 키캡 스타일의 키 표시 |
| 비순서 / 순서 목록 | `- 항목` / `1. 항목` | 나열하거나 단계별인 내용 정리 |
| 작업 목록 | `- [x] 완료됨` | 체크박스가 있는 확인 목록 |
| 인용 블록 | `> 인용문` | 원문 인용, 곁가지 설명 보충 |
| 코드 블록 | 백틱 세 개로 감쌈 | 여러 줄 코드, 하이라이트와 복사 버튼 포함 |
| 표 | 세로줄로 열 구분 | 파라미터 대조, 데이터 나열 |
| 링크 | `[텍스트](주소)` | 사이트 내 다른 페이지나 외부 사이트로 이동 |
| 이미지 | `![설명](경로)` | 스크린샷, 아키텍처 다이어그램 삽입 |
| 구분선 | `---` | 큰 단락 구분 |

### 3.1 제목 단계

본문에서는 **1단계 제목(`#`)을 쓰지 마세요**. Frontmatter의 `title`이 이미 페이지 큰 제목으로 자동 렌더링되므로, 본문에 `#`을 하나 더 쓰면 페이지에 큰 제목이 두 개 생깁니다. 각 소절은 2단계 제목(`##`)부터 시작합니다:

```markdown
## 2단계 큰 제목 (장)

### 3단계 하위 제목 (소절)
```

**렌더링 결과**: 지금 읽고 있는 이 페이지가 바로 좋은 예입니다. "3. 기본 Markdown 형식 전체 보기"가 2단계 제목이고 이 소절 "3.1 제목 단계"가 3단계 제목이며, 둘 다 오른쪽 "이 페이지의 목차"에 나타납니다. 4단계 제목(`####`)은 본문 스타일만 적용되고 목차에는 더 이상 들어가지 않으므로, 목차에 넣고 싶지 않은 잘게 나뉜 소절에 적합합니다.

### 3.2 단락과 줄바꿈

Markdown은 빈 줄로 단락을 구분합니다. 초보자가 가장 많이 실수하는 부분입니다:

```markdown
이것은 첫 번째 단락으로, 두 문장 사이에서 Enter를 한 번만 눌렀기
때문에 렌더링 후에도 같은 단락에 머뭅니다.

이 줄은 위 문장과 빈 줄 하나를 사이에 두고 있어, 렌더링하면 새 단락으로 나뉩니다.

이 줄의 끝에는 백슬래시가 하나 있고\
그 아래 줄은 실제로 새 줄에서 시작합니다.
```

**렌더링 결과:**

이것은 첫 번째 단락으로, 두 문장 사이에서 Enter를 한 번만 눌렀기
때문에 렌더링 후에도 같은 단락에 머뭅니다.

이 줄은 위 문장과 빈 줄 하나를 사이에 두고 있어, 렌더링하면 새 단락으로 나뉩니다.

이 줄의 끝에는 백슬래시가 하나 있고\
그 아래 줄은 실제로 새 줄에서 시작합니다.

규칙 요약: **Enter 한 번 = 소스 코드에서는 줄이 바뀌어도 같은 단락**. 새 단락을 시작하려면 빈 줄을 넣고, 단락 안에서 강제로 줄을 바꾸려면 줄 끝에 백슬래시나 공백 두 개를 사용합니다.

### 3.6 코드 블록

백틱 세 개로 감싸고 첫 줄 백틱 뒤에 언어를 표기하면 문법 하이라이트가 적용됩니다. 각 코드 블록 오른쪽에는 한 번에 복사하는 버튼이 기본으로 붙습니다:

````markdown
```js
export function formatBytes(bytes) {
  return `${(bytes / 1024).toFixed(1)} KB`;
}
```
````

**렌더링 결과:**

```js
export function formatBytes(bytes) {
  return `${(bytes / 1024).toFixed(1)} KB`;
}
```

언어 식별자가 하이라이트 방식을 결정하며, 자주 쓰는 `js`, `ts`, `bash`, `json`, `yaml`, `html`, `css`, `python` 등을 모두 지원합니다. `bash` 같은 터미널 언어는 터미널 스타일의 어두운 테두리로 렌더링됩니다:

```bash
pnpm run build
```

코드 블록의 파일 이름 제목, 지정 줄 하이라이트 등 고급 사용법은 4.2절을 참고하세요.

- **아키텍처 다이어그램과 순서도**: `.svg` 벡터 이미지로 저장하면 모바일과 고해상도 화면에서 확대해도 흐려지지 않습니다. 이 사이트의 아키텍처 다이어그램은 모두 `public/images/canvas/docs-*.svg`에 있습니다.
- **UI 스크린샷**: 압축한 `.png`로 저장하고 너비는 1440픽셀 정도면 충분합니다. 수십 MB짜리 원본을 그대로 올리지 마세요.
- **설명 텍스트 필수**: `![ ]` 안의 텍스트는 이미지의 대체 텍스트로 렌더링되므로, 이미지 내용을 성실히 설명하고 비워 두지 마세요.

이미지를 넣은 뒤에는 **반드시 브라우저에서 실제 렌더링 결과를 확인**하고, 경로가 올바르고 이미지가 정상적으로 표시되는지 확인한 후 커밋하세요.

### 3.10 구분선

짧은 대시 세 개 이상이 한 줄을 차지하면 구분선으로 렌더링되며, 큰 단락을 나누는 데 사용합니다:

```markdown
위의 내용은 여기까지입니다.

---

아래에서 새 주제를 시작합니다.
```

**렌더링 결과:**

위의 내용은 여기까지입니다.

---

아래에서 새 주제를 시작합니다.

:::caution
구분선 바로 위에는 빈 줄을 하나 남겨야 합니다. 텍스트 바로 다음 줄에 붙은 `---`는 "또 다른 제목 표기법"으로 인식되어 윗줄의 텍스트가 큰 제목으로 렌더링됩니다.
:::

## 4. 확장 형식: 이 사이트의 강화 문법

아래 형식은 이 사이트가 표준 Markdown 위에 추가로 지원하는 확장 문법으로, 렌더링 엔진(Starlight 콜아웃과 Expressive Code)이 제공합니다.

### 4.1 네 가지 색상 콜아웃

콜아웃은 콜론 세 개 문법을 사용합니다. `:::타입`으로 시작하고 한 줄에 `:::`만 있는 줄로 끝나며, 네 가지 타입이 있고 색상과 아이콘이 각각 다릅니다:

:::note
**note(보충 설명)**: 배경 지식, 설계 세부 사항, 선행 의존성.
:::

:::tip
**tip(실용 팁)**: 효율을 높이는 요령, 베스트 프랙티스.
:::

:::caution
**caution(주의 경고)**: 실수하기 쉬운 조작, 잠재적인 호환성 문제.
:::

:::danger
**danger(고위험 알림)**: 데이터 손실, 프로덕션 환경 덮어쓰기 등 되돌릴 수 없는 조작.
:::

타입 뒤에 대괄호를 붙이면 제목을 직접 정할 수 있습니다:

````markdown
:::tip[설치 속도 높이기]
pnpm으로 의존성을 설치하면 npm보다 훨씬 빠릅니다:

```bash
npm install -g pnpm
```
:::
````

**렌더링 결과:**

:::tip[설치 속도 높이기]
pnpm으로 의존성을 설치하면 npm보다 훨씬 빠릅니다:

```bash
npm install -g pnpm
```
:::

콜아웃 안에서는 목록, 코드 블록, 표 등 어떤 조판이든 계속 사용할 수 있습니다. 더 많은 예시는 [콜아웃, 코드 블록 및 다이어그램 예시](/canvas/syntax/)를 참고하세요.

### 4.2 코드 블록 파일 이름 제목과 줄 하이라이트

코드 펜스 첫 줄에 `title="파일 경로"`를 표기하면 제목 표시줄이 나타나고, `{줄 번호}`로 중요한 줄을 하이라이트하며, 여러 줄 번호는 쉼표로 구분합니다:

````markdown
```typescript title="src/config/site.ts" {2,4}
export const siteConfig = {
  name: 'EpoCanvas Docs', // ← 하이라이트 줄
  version: '1.0.0',
  locale: 'zh-CN',        // ← 하이라이트 줄
};
```
````

**렌더링 결과:**

```typescript title="src/config/site.ts" {2,4}
export const siteConfig = {
  name: 'EpoCanvas Docs',
  version: '1.0.0',
  locale: 'zh-CN',
};
```

### 4.3 diff 변경 비교

`diff` 언어로 설정 변경 사항을 보여 주며, `-`로 시작하는 줄은 삭제, `+`로 시작하는 줄은 추가로 표시됩니다:

````markdown
```diff
  export default defineConfig({
-   site: 'http://localhost:3000',
+   site: 'https://docs.epocanvas.com',
  });
```
````

**렌더링 결과:**

```diff
  export default defineConfig({
-   site: 'http://localhost:3000',
+   site: 'https://docs.epocanvas.com',
  });
```

### 4.4 각주

자료 출처를 밝히거나 보충 설명을 달 때는 GFM 각주 문법을 사용합니다:

````markdown
사이트 전체 검색 인덱스는 Pagefind가 빌드 시점에 생성합니다[^pf].

[^pf]: [Pagefind 공식 문서](https://pagefind.app/) — 정적 사이트를 위한 로컬 검색 라이브러리.
````

**렌더링 결과:** 본문에 번호가 붙은 윗첨자 이동 표시[^md-page]가 나타나고, 클릭하면 페이지 맨 아래의 해당 각주 항목으로 부드럽게 이동합니다.

[^md-page]: 바로 이것이 이 페이지 맨 아래에 렌더링된 각주 본체입니다. 각주 내용은 본문 어디에 쓰든 페이지 맨 아래로 모두 모입니다.

### 4.5 지원하지 않는 문법과 실수하기 쉬운 표기 빠른 참조

아래 표기법은 다른 플랫폼에서 흔하지만 이 사이트에서는 **동작하지 않거나** 기대와 다르게 표현되므로, 문서를 쓸 때는 처음부터 피하세요:

| 실수하기 쉬운 표기법 | 실제 동작 | 올바른 대체 |
| :--- | :--- | :--- |
| <code>```mermaid</code> 펜스 | 일반 코드 블록처럼 소스가 그대로 표시되며 도형이 생성되지 않음 | mermaid.live에서 SVG로 내보낸 뒤 이미지로 삽입 |
| `> [!NOTE]` GitHub 알림 문법 | 일반 인용 블록으로 렌더링됨 | `:::note`로 다시 씀 |
| `:::warning` / `:::important` | 알림 없이 조용히 일반 단락으로 렌더링되어 콜아웃 스타일이 없음 | `:::caution`으로 다시 씀 |
| 본문에 1단계 제목 `#` 쓰기 | 페이지에 큰 제목이 두 개 생김 | `#`을 지우고 본문은 `##`부터 시작 |
| Enter 한 번으로 줄바꿈 | 두 줄이 한 줄로 합쳐짐 | 빈 줄로 단락을 나누거나 줄 끝에 백슬래시 추가 |
