**EpoCanvas Docs** 内置了完整的内容级多语言：导航栏、侧边栏、搜索提示等界面文字，以及每一篇文档的正文，都提供 10 种语言的独立版本。读者在页面右上角选择语言后，会跳转到同一篇文章的目标语言版本，正文与界面一起切换。

---

## 支持的语言列表

站点目前提供 10 种语言，其中简体中文是默认语言：

| 语言 | 语言名称 | URL 前缀 | 界面缩写 |
| :--- | :--- | :--- | :--- |
| 简体中文 | **简体中文**（默认） | 无前缀 | ZH |
| 繁體中文 | 繁體中文 | `/zh-tw/` | TW |
| English | 英语 | `/en/` | EN |
| 日本語 | 日语 | `/ja/` | JA |
| 한국어 | 韩语 | `/ko/` | KO |
| Español | 西班牙语 | `/es/` | ES |
| Français | 法语 | `/fr/` | FR |
| Deutsch | 德语 | `/de/` | DE |
| Русский | 俄语 | `/ru/` | RU |
| Português | 葡萄牙语 | `/pt/` | PT |

语言清单定义在 `src/utils/i18n.ts` 的 `SUPPORTED_LANGUAGES` 中；`astro.config.mjs` 的 `locales` 注册路由，`LOCALE_DIRS` 识别非默认语言目录。新增语言时还要同步翻译字典与检查脚本，不能只改 `locales`。

## 如何切换语言

1. 在页面顶部导航栏右侧找到语言按钮（显示当前语言的缩写，如 `ZH`）；
2. 点击按钮，下拉菜单列出全部 10 种语言；
3. 点击目标语言（例如 `English` 或 `日本語`）；
4. 浏览器跳转到当前这篇文章的目标语言版本，导航、侧边栏、目录与正文一起变成目标语言。

## URL 规则

每种语言的页面有独立的 URL 前缀，同一篇文章在不同语言下只有前缀不同：

```text
/canvas/i18n/          → 简体中文（默认语言，无前缀）
/en/canvas/i18n/       → 英文
/ja/canvas/i18n/       → 日文
/zh-tw/canvas/i18n/    → 繁体中文
```

- 语言信息直接编码在 URL 里，切换后的页面可以直接收藏、分享，搜索引擎也能按语言分别收录；
- 页面内出现的站内链接（导航、侧边栏、正文中的推荐链接）都会自动带上当前语言的前缀，读者在某一语言内连续阅读时不会跳回中文页；
- 每个语言版本都是构建期生成的独立静态页面，页面的 `<html lang>` 属性与语言一致，屏幕阅读器和翻译工具可以正确识别。

## 译文缺失怎么办

Starlight 在某篇文档缺少译文时，可以用默认的简体中文正文生成目标语言路由。这是框架的技术兜底，不是本项目允许的发布方式：页面的语言声明可能仍是目标语言，正文却是中文。

本项目要求首页和全部正文在 10 种语言中成套维护。`node scripts/audit-i18n.mjs` 会检查缺页、多余页、Frontmatter、标题与代码围栏结构；缺译会返回非零退出码，阻断 `pnpm run verify` 和 CI。新增或修改文档时，必须同步完成全部语言的对应内容再发布，不能先发中文版、之后补译。仅运行 `pnpm run build` 成功不代表通过发布检查。

## 实现原理

多语言能力由 Astro 与 Starlight 的国际化机制承载，构建流程如下：

1. **内容目录按语言划分**：默认语言的文档放在 `src/content/docs/`（简体中文），其他语言放在 `src/content/docs/<语言>/` 下，目录结构与中文完全对应，例如英文版《多语言支持与阅读切换》是 `src/content/docs/en/canvas/i18n.md`；
2. **构建期生成全部语言页面**：`astro build` 读取 `astro.config.mjs` 中的 `locales` 配置，为每种语言生成一套完整静态页面；
3. **界面词条按语言渲染**：顶栏导航、搜索提示、目录标题等界面文字由各组件调用 `getTranslation(key, lang)` 在构建期直接输出对应语言，页面里没有运行时替换脚本；
4. **正文内链自动本地化**：构建管线中的 `rehypeLocalizeInternalLinks` 插件会把译文正文里的 `/canvas/xxx` 内链自动加上当前语言前缀；
5. **全文搜索按语言隔离**：Pagefind 为每种语言建立独立索引，在英文页面搜索只会返回英文结果。
6. **正文图片本地化与检查**：`rehypeLocalizeDiagramImages` 在存在同名译图时，把 `/images/canvas/<文件名>` 改为 `/images/canvas/<语言>/<文件名>`；否则技术上保留原图。但发布检查 `check-localized-images.mjs` 要求对应语言图片齐全，只有 `SHARED_ALLOWLIST` 中登记的第三方界面截图等真正共享图片可以例外，不能靠原图回退绕过翻译；
7. **提示框与脚注按语言输出**：`rehypeLocalizeAsides` 与 `rehypeLocalizeFootnotes` 按源文件所在语言目录改写提示框标题和脚注文案——Starlight 在 remark 阶段按文件绝对路径推断语言，本机构建传给它的是相对路径，不处理就会全部回落成中文；
8. **hreflang 与 404 页**：`hreflangXDefault()` 在构建完成后为每个页面补一条 `hreflang="x-default"`，指向简体中文版本；`src/pages/404.astro` 复用同一份词条字典按浏览器语言输出提示文案，页面上的语言菜单指向各语言首页。

## 开发者：如何新增一种语言？

以新增意大利语（Italiano，代码 `it`）为例：

1. **注册路由与目录**：在 `astro.config.mjs` 的 `locales` 加入 `it: { label: 'Italiano', lang: 'it' }`，同时在 `LOCALE_DIRS` 加入 `it`，让内链、图片、重定向与语言声明处理识别新目录。
2. **翻译侧边栏、提示框与脚注**：补齐同一文件的 `SIDEBAR_I18N`；在 `LOCALE_TRANSLATION_FILES` 登记 `it: 'it.json'`，并补充 `FOOTNOTE_LABELS` 与 `FOOTNOTE_BACK_LABELS` 的意大利语文案。
3. **翻译界面词条**：在 `src/utils/i18n.ts` 的 `SUPPORTED_LANGUAGES` 登记代码、名称、缩写与目录，在 `UI_TRANSLATIONS` 补齐全部键，包括搜索、Pagefind 与 404 提示。
4. **翻译全部内容**：创建 `src/content/docs/it/index.mdx`，并在 `src/content/docs/it/canvas/` 放入与默认语言一一对应的完整译文。保持 Frontmatter 字段、标题层级与代码围栏结构一致；复制中文占位不算完成翻译。
5. **准备本地化图片**：将同名译图放入 `public/images/canvas/it/`，仅真正共享的图片可登记到 `scripts/check-localized-images.mjs` 的 `SHARED_ALLOWLIST`。使用现有图表生成工具时，补充 `scripts/diagram-i18n/it.mjs` 并在 `scripts/generate-diagram-locales.mjs` 的 `LOCALES` 登记；使用截图工具时，同步 `scripts/capture-ui-shots.mjs` 的 `LOCALES` 与 `SEARCH_WORDS`。
6. **同步检查范围**：在 `scripts/audit-i18n.mjs` 的 `locales` 和 `LATIN` 加入 `it`；在 `scripts/check-anchors.mjs` 的 `LOCALES`、`scripts/check-localized-images.mjs` 的 `LOCALE_DIRS` 加入 `it`；在 `scripts/check-links.mjs` 的语言码与目录映射 `LANG_DIRS` 加入 `['it', 'it']`。`scripts/check-images.mjs` 自动递归扫描全部图片目录，无须另加语言清单。
7. **先检查源文件与图片**：在仓库根目录运行 `node scripts/audit-i18n.mjs` 和 `node scripts/check-images.mjs`。后者只检查 PNG 文件头与最小体积，不能代替人工核对图中文字和布局。
8. **完整验证后发布**：运行 `pnpm run verify`，完成构建后会检查本地化图片引用、链接、锚点与语言声明；再用 `pnpm run preview` 检查新语言首页、正文、语言切换和全站搜索。修复全部失败项，不要通过删除检查来发布。

## 开发者：如何新增或修改界面词条？

新增界面元素时，在 `src/utils/i18n.ts` 的 `UI_TRANSLATIONS` 中补充词条：

```typescript
// 文件路径: src/utils/i18n.ts
// 字典按「语言 → 词条键」两级组织，与 getTranslation 的读取顺序一致
export const UI_TRANSLATIONS: Record<string, Record<string, string>> = {
  // 第一步：在默认语言 zh-CN 里加词条（缺失时界面回退显示键名）
  'zh-CN': {
    'nav.plugins': '插件生态',
    // ...其余已有词条
  },
  // 第二步：给其它语言补同一键名的翻译，没补的语言自动回退中文
  en: {
    'nav.plugins': 'Plugins',
  },
  ja: {
    'nav.plugins': 'プラグイン',
  },
};
```

然后在组件中调用 `getTranslation` 并传入当前语言：

```astro
---
import { getLangFromLocale, getTranslation, localizedHref } from '../../utils/i18n';
const lang = getLangFromLocale(Astro.currentLocale);
---

<a href={localizedHref('/plugins/', lang)}>{getTranslation('nav.plugins', lang)}</a>
```

词条在构建期渲染为对应语言的静态文字，没有运行时开销。

上例只节选了三个语言分支；新增词条仍须在全部已注册语言中补齐。中文回退仅用于容错，不能当作翻译完成。
