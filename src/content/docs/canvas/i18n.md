作为面向全球开发者的开源专案，**EpoCanvas Docs** 内置了轻量的**界面多语言切换功能**。读者可以随时把导航栏、搜索框提示、目录标题等界面文字切换成自己熟悉的语言。

先说清楚一个边界：**多语言切换只作用于界面元素，不翻译文档正文**。正文内容保持撰写时的语言（本站正文为简体中文），这样既保证了技术内容的准确性，也避免维护十份重复的译文。

---

## 支持的语言列表

系统目前内置了 10 种界面语言，定义在 `src/utils/i18n.ts` 中：

| 语言代码 | 语言名称 | 界面缩写 |
| :--- | :--- | :--- |
| `zh-CN` | **简体中文**（默认） | ZH |
| `zh-TW` | 繁體中文 | TW |
| `en` | English（英语） | EN |
| `ja` | 日本語（日语） | JA |
| `ko` | 한국어（韩语） | KO |
| `es` | Español（西班牙语） | ES |
| `fr` | Français（法语） | FR |
| `de` | Deutsch（德语） | DE |
| `ru` | Русский（俄语） | RU |
| `pt` | Português（葡萄牙语） | PT |

## 如何在页面上切换语言

1. 在页面顶部导航栏右侧找到语言切换按钮（默认显示 `ZH`）；
2. 点击按钮，下拉菜单列出所有支持的语言选项；
3. 点击目标语言（例如 `English` 或 `日本語`）；
4. 页面导航栏按钮、搜索框提示语等界面文字立即就地刷新，当前阅读位置不受影响，页面不重新加载。

你的选择会自动保存在浏览器的 LocalStorage（键名 `epocanvas-lang`）中，下次打开网站时自动套用。如果某个词条暂时缺少对应语言的翻译，界面会回退显示默认中文，不会出现空白或报错。

## 实现原理

很多传统文档系统为了支持 10 种语言，会在构建时生成 10 份重复的静态站点（例如 `/zh/`、`/en/`、`/ja/`），带来三个问题：

- 打包体积成倍膨胀；
- 每次切换语言必须整页刷新，滚动位置丢失；
- 未翻译的文章切换后直接 404。

EpoCanvas Docs 采用**前端字典替换方案**：

- 系统统一维护一份界面翻译字典（位于 `src/utils/i18n.ts`）；
- 点击切换时，脚本在几毫秒内把页面上带有 `data-i18n` 标记的界面文字替换为目标语言；
- 没有对应翻译的词条自动回退为中文默认值。

## 开发者：如何添加或修改翻译词条？

如果你在二次开发中新增了导航按钮或界面元素，打开 `src/utils/i18n.ts` 补充词条即可：

```typescript
// 文件路径: src/utils/i18n.ts
export const UI_TRANSLATIONS: Record<string, Record<string, string>> = {
  // 新增一个导航条目翻译
  'nav.plugins': {
    'zh-CN': '插件生态',
    'zh-TW': '外掛生態',
    en: 'Plugins',
    ja: 'プラグイン',
    ko: '플러그인',
    de: 'Plugins',
    fr: 'Extensions',
    es: 'Complementos',
    ru: 'Плагины',
    pt: 'Plugins',
  },
};
```

然后在对应的 `.astro` 模板中为 HTML 标签加上属性即可生效：

```html
<a href="/plugins/" data-i18n="nav.plugins">插件生态</a>
```

维护成本就是一份字典文件，不需要引入任何国际化框架。
