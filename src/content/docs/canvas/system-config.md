# Markdown 编写与排版指南

在 **EpoCanvas Docs** 中添加或编辑文档非常轻松。所有的正文内容都是用标准的 **Markdown** 语法编写的。只要你会写 Markdown，就能立即参与到文档的撰写和维护中。

---

## 1. 文档文件放在哪里？

所有文档文件都存放在项目的 `src/content/docs/` 目录下：

```text
src/content/docs/
├── index.mdx          # 网站的落地首页
└── canvas/            # 核心文档章节
    ├── index.md       # 产品简介
    ├── deployment.md  # 快速上手
    ├── ...            # 其他文档
```

- **文件名要求**：使用小写英文字母和中划线（例如 `quickstart-guide.md`），不要包含中文或空格。
- **扩展名**：通常使用纯文本的 `.md` 文件即可；如果需要在文章中引入可交互的前端组件，可以使用 `.mdx` 格式。

---

## 2. 头部元数据 (Frontmatter) 怎么写？

每一篇 Markdown 文档的最上方，都必须包含用三个横线 `---` 包裹的 YAML 元数据块，用来定义文章的基本信息：

```yaml
---
title: 快速上手 (3分钟运行)
description: EpoCanvas Docs 本地环境准备、安装依赖与启动服务指南。
---
```

### 字段说明：
| 字段名称 | 是否必填 | 作用说明 |
| :--- | :--- | :--- |
| `title` | **必填** | 文章主标题。会作为页面大标题（h1）展示，并作为浏览器标签页标题。 |
| `description` | 建议填写 | 文章的简短摘要。用于浏览器搜索结果、社交平台分享卡片的描述文字。 |
| `sidebar.label` | 可选 | 当文章标题较长时，可以在左侧目录树中显示一个更精简的短名称。 |
| `sidebar.order` | 可选 | 排序数字。数字越小在当前分类中排得越靠前。 |

> [!TIP]
> 如果你在写文档时忘记写 `title`，Astro 会在终端明确提示 `[AstroContentError] "title" is required` 并指出文件名，提醒你补充完整。

## 3. 常用 Markdown 排版格式

### 3.1 标题层级
正文中的各级小节标题建议从二级标题（`##`）开始使用，右侧大纲（TOC）会自动抓取二级标题和三级标题生成目录：

```markdown
## 二级大标题（会被收录进右侧大纲）

正文内容...

### 三级子标题（大纲中的子项）

更细节的内容...
```

### 3.2 文字强调与行内样式
```markdown
这是**加粗文字**，这是*斜体文字*，这是~~删除线~~。
你也可以使用行内代码标识符：`pnpm run dev`。
```

### 3.3 列表与任务清单
```markdown
无序列表：
- 第一项功能
- 第二项功能
  - 缩进子功能

有序列表：
1. 第一步：安装 Node.js
2. 第二步：克隆代码仓库
3. 第三步：启动本地服务
```

### 3.4 表格排版
```markdown
| 参数名称 | 类型 | 默认值 | 说明 |
| :--- | :--- | :--- | :--- |
| `site` | string | `undefined` | 站点的线上生产域名 |
| `title` | string | 必填 | 网站标题 |
```

## 4. 如何在文档中插入图片？

我们推荐把文档所需的图片资产统一放在 `public/images/canvas/` 目录下：

```text
public/
└── images/
    └── canvas/
        ├── screenshot.png
        └── diagram.svg
```

在 Markdown 中插入图片时，使用以 `/` 开头的绝对路径即可引用：

```markdown
![图片说明文字](/images/canvas/screenshot.png)
```

**图片选择建议**：
- **架构图与流程图**：优先推荐保存为 `.svg` 矢量图格式，在手机和高清 Retina 屏幕上放大都不会模糊。
- **界面操作截图**：保存为清晰的 `.png` 或经过压缩的 `.webp`，建议宽度在 1200~1600 像素左右，不要直接上传几十兆未经压缩的照片原图。
